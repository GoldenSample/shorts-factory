# ВИЗУАЛ БЕЗ ГЕНЕРАТИВА: замеренные приёмы

Всё прогнано на этой машине: **ffmpeg 8.1.2-full (gyan), RTX 5090, Vulkan/libplacebo в сборке есть.**
Команды скопированы из отработавших вызовов.

## ⚑ ГЛАВНАЯ НАХОДКА: zoompan ЗАМОРАЖИВАЕТ КАДРЫ

Замер (слабый пан 0.216 выходного пикселя за кадр, субпиксельный центроид пятна по кадрам):

| Метод | шаг/кадр | stdev | jitter | **замороженных кадров** |
|---|---|---|---|---|
| `zoompan` напрямую | −0.2139 | 0.2642 | 1.235 | **90 из 149** |
| `scale` 2x → zoompan | −0.2156 | 0.1087 | 0.504 | 30 из 149 |
| `scale` 4x → zoompan | −0.2072 | 0.0641 | 0.310 | 0 из 149 |
| **`libplacebo` (Vulkan)** | −0.2163 | **0.0191** | **0.088** | **0 из 149** |

Голый `zoompan` на медленном движении стоит 90 кадров из 149, потом дёргается скачком ~0.5px —
это и есть «стробит». Причина: `zoompan` округляет и смещение, и размер кропа **до целого пикселя**,
опции субпиксельности у него нет. Пересемплинг лечит симптом, libplacebo лечит причину (режет по float).

Скорость на 5-секундном 1080x1920: `scale=12000:8000`+zoompan = **3.78 с**, libplacebo = **1.57 с**.
**В 2.4 раза быстрее и в 3.4 раза плавнее.**

⚠ Наш `forge.py` сейчас на голом zoompan (`build_kenburns`) → там ровно эта заморозка.

## KEN BURNS: рабочий вариант (libplacebo)

```bash
ffmpeg -y -init_hw_device vulkan=vk -filter_hw_device vk \
  -loop 1 -framerate 30 -t 5 -i src.png \
  -vf "format=rgba,hwupload,\
libplacebo=w=1080:h=1920:\
crop_w='iw/(1+0.0008*n)':crop_h='ih/(1+0.0008*n)':\
crop_x='(iw-cw)/2':crop_y='(ih-ch)/2':\
upscaler=ewa_lanczos:format=yuv420p,\
hwdownload,format=yuv420p,setsar=1" \
  -c:v libx264 -crf 18 -pix_fmt yuv420p out.mp4
```
Переменные в `crop_*`: `iw ih` вход, `cw ch` текущий кроп, `n` номер кадра, `t` время.
Пан+наезд по времени (устойчивее к смене fps): `crop_w='iw/(1+0.25*t/5)'`, `crop_x='(iw-cw)*(0.35+0.30*t/5)'`.

**Фолбэк без Vulkan:** `scale=12000:8000:flags=lanczos` перед zoompan (порядок обязателен —
наоборот бессмысленно, округление уже произошло). 4x — потолок полезности, дальше растёт только время.

Грабли zoompan: идиома `d=1` при `-loop 1 -framerate 30 -t 5` (в выражениях работает `on`);
не задать `x`/`y` = пан в левый верхний угол; `setsar=1` в конце всегда.

## ⛔ БЕСШОВНАЯ ЗАКОЛЬЦОВКА ФУТАЖА (замерено, врезано в forge.py)

Генератив отдаёт клип 4-8 секунд, а крутить его надо под озвучку 15-60. Тупая петля
(`-stream_loop -1`) стыкует последний кадр с первым — **и это видно каждый оборот**.
Глаз ловит именно РИТМИЧНОСТЬ рывка, поэтому дефект читается как дешёвая склейка.

**Замер на живом грок-футаже (8.04с, 24fps) с озвучкой 31.4с:**

| | максимум скачка | рывки |
|---|---|---|
| **тупая петля** | **x28.2** от обычного хода | **4 штуки: 8.0 · 16.1 · 24.1 · 32.1 с** — ровно каждый оборот |
| **бесшовная** | x2.3 | **ноль** |

### Критерий бесшовности (объективный, не на глаз)

`seam_ratio = разница на стыке / медианная межкадровая разница внутри клипа`.
~1.0 — стык неотличим от рядового перехода · >2.0 заметен · >4.0 бьёт в глаз. Порог приёмки **1.6**.
⚑ **Мерить именно ОТНОШЕНИЕМ, не абсолютом:** у спокойного клипа любой скачок заметен,
у динамичного тот же абсолют тонет в движении.

### ⛔ ЗАМЫКАНИЕ ПРОТИВ МАСКИРОВКИ — разные вещи

**Точное (покадровое) замыкание** — петля стыкуется КАДРОМ САМА С СОБОЙ, движение через
границу непрерывно, файл можно крутить по кругу вечно. Это и есть tape loop.
**Маскировка** — шов замазан растворением: картинка на переходе двоится, кадры физически
не совпадают. Метрика может быть отличной, а по кругу такое крутить нельзя.

| Стратегия | Замер на грок-футаже | Замыкание |
|---|---|---|
| **pingpong** — прямой ход + реверс | **x0.72 ← выбирается** | **ТОЧНОЕ** |
| **cut** — резать петлю по паре похожих кадров | x23.72 — мимо | точное (но не нашлось) |
| **xfade** — начало скрещено с хвостом | x0.6 | маскировка |
| **morph** — мост через `minterpolate` | **x23.5 — не работает** | — |

⚑ **`pingpong` — единственная стратегия с точным замыканием на генеративном футаже.**
Замер готовой петли: стык x0.72, **максимальный скачок по всей петле x1.3**, залипаний ноль.
На боевой сцене (31с озвучки, 4 оборота): максимум x1.7, **рывков ноль**.

⚑ **Обрезать дубли на разворотах ОБЯЗАТЕЛЬНО.** Наивный `[a][r]concat` дублирует кадр
и в конце прямого хода, и на замыкании — на воспроизведении это двойное залипание каждый оборот.
Правильно: `reverse,trim=start_frame=1:end_frame=N-1`, то есть `A0..An-1 + A(n-2)..A1`.

⚠ Цена `pingpong` — маятник на направленном движении (дым вверх → вниз, пролёт камеры).
Для абстрактных текстур, боке, частиц и дыма незаметен. **Настоящее лечение — просить
у генератора циклическое движение промптом**, тогда сработает `cut` и маятник не понадобится.

⛔ **`cut` на грок-футаже почти всегда мимо:** модель уводит композицию необратимо,
похожих кадров в клипе просто нет.
⛔ **`morph` через `minterpolate` НЕ РАБОТАЕТ** и это замерено: стык остаётся x23.4-23.7
**при любой длине моста** (16 / 32 / 48 кадров — без разницы). Оптический поток рассчитан
на соседние кадры; между кадрами, разошедшимися на 8 секунд, потока нет и мост не строится.
Не тратить на это время.

⚠ Побочная находка: клип 24fps, приведённый к `fps=30` в сборке сцены, получает **2% дублей
кадров** (апсемплинг дублированием). Сама петля при этом чистая — 0%. Если важна гладкость,
приводить fps интерполяцией или держать исходный.

### Реализация

`projects/shorts-forge/seamless.py` — `make_loop(src, dst, mode="auto")`, врезано в `build_scene`.
```
python seamless.py клип.mp4                       # авто: замерит все три, выберет и отчитается
python seamless.py клип.mp4 --mode xfade --seconds 30
```
⚠ **Грабля `blend`:** внутри выражения переменная времени называется `T`, поэтому длительность
клипа в коде обозначена `dur` — иначе выражение молча считает не то.
⚠ Статичный кадр (заглушка, Ken Burns по статике) закольцовки **не требует** — он бесшовен
по построению. Определять по медианному ходу < 0.05, иначе деление на ноль роняет анализ.

## ПАРАЛЛАКС ИЗ ОДНОГО ИЗОБРАЖЕНИЯ

`displace` берёт 3 входа (картинка, xmap, ymap), смещение = `значение_карты − 128`:
```bash
-filter_complex "\
[1:v]format=gray,geq=lum='128+(p(X,Y)-128)*0.5*sin(2*PI*T/4)'[xm];\
[1:v]format=gray,geq=lum='128'[ym];\
[0:v]format=rgb24[base];[base][xm][ym]displace=edge=smear[v]"
```
Амплитуда — множитель `0.5`; выше 1.0 лезут разрывы. `edge=smear` замазывает края.
Карту глубины брать **Depth Anything V2** нодой в ComfyUI. ⚠ Модель на машине НЕ стоит —
проверен только ffmpeg-конец цепочки на синтетическом градиенте.

Слоями (качественнее): 2-3 слоя PNG с альфой, скорости кратны глубине (40/90/190 px),
`overlay` с выражениями по `t`. ⚠ `overlay` тоже целочисленный — на медленном ходу та же лестница,
держать скорость от ~1.5 px/кадр либо гнать слои через libplacebo.

## ГРАФИКИ И ЦИФРЫ

Столбики: `drawbox` с выражениями, ступенчатый старт через `max(t-задержка,0)`, потолок через `min`:
```
drawbox=x=140:y='1500-min(max(t-0.0\,0)*700\,420)':w=140:h='min(max(t-0.0\,0)*700\,420)':color=0x58a6ff:t=fill
```
⚠ **Запятые внутри выражений экранировать `\,`** — иначе ffmpeg рвёт фильтрграф по запятой.
Это самая частая причина «Invalid argument».

Счётчик: `drawtext=text='%{eif\:1200+t*3450\:d}'` (`\:u` без знака, `\:d\:6` с ведущими нулями).

Линия по реальным данным: чистый ffmpeg не годится (массив не скормить) → генерить PNG-кадры
и собирать `-framerate 30 -i frames/%05d.png`. ⚠ numpy/PIL в системном python нет, ставить в venv.
Дешёвая альтернатива: нарисовать финальный график один раз и **вскрывать шторкой**
`crop=w='min(iw*t/3\,iw)'`.

## КИНЕТИЧЕСКИЙ ТЕКСТ: ASS, не drawtext

`drawtext` не умеет ни выезд, ни масштаб-анимацию, ни караоке. Всё это в ASS одной строкой.
```
Dialogue: 0,0:00:00.00,0:00:01.60,Kin,,0,0,0,,{\fad(150,150)\move(540,1120,540,960,0,400)}ЦЕНА УПАЛА
Dialogue: 0,0:00:01.60,0:00:03.20,Kin,,0,0,0,,{\pos(540,960)\fscx60\fscy60\t(0,350,\fscx115\fscy115)\t(350,500,\fscx100\fscy100)}НА 40 ПРОЦЕНТОВ
```
`\move(x1,y1,x2,y2,t1,t2)` выезд · `\fad(in,out)` мс · `\t(t1,t2,теги)` анимация чего угодно
(`\fscx130` пружина, `\frz15` поворот, `\blur4`) · `\k45` караоке 0.45с.
⚠ Цвета в ASS **`&HBBGGRR`**, порядок обратный HTML. `Alignment 5` = центр-центр, удобнее для вертикали.
`Outline 7` + `Shadow 4`, иначе на пёстром фоне текст съедается.

## ПЕРЕХОДЫ (xfade, 58 штук в сборке)

```bash
-filter_complex "[0][1]xfade=transition=slideup:duration=0.3:offset=2.7"
```
⚠ `offset` — момент **начала** перехода на общем таймлайне, а не от конца первого клипа:
`offset = длительность_первого − duration`. Все входы обязаны совпадать по разрешению, fps и SAR —
иначе `xfade` молча выдаёт мусор.

Вертикальный кадр читается сверху вниз → вертикальные движения родные, горизонтальные читаются
как ошибка формата. **Рабочие:** `slideup`, `wipeup`, `smoothup`, `fade`, `dissolve`, `circleopen`.
**Избегать:** `slideleft/right`, `hlslice`, `pixelize`, спиральные. Длительность **0.2-0.4 с**,
полсекунды на шортсе уже провисание.

## СКРИНКАСТ 16:9 → 9:16

**Размытая подложка:** оригинал `scale=1080:-2` поверх `scale=1080:1920:force_original_aspect_ratio=increase,
crop=1080:1920,gblur=sigma=40,eq=brightness=-0.15`.

**Подсветка области:** клонируем кадр (`split`), одну копию гасим (`eq=brightness=-0.35:saturation=0.4`),
из второй вырезаем прямоугольник и кладём поверх на своё же место + `drawbox` рамкой,
всё с `enable='between(t,0.8,2.5)'`.

**Наезд на элемент:** только libplacebo — на скринкасте с текстом целочисленный zoompan виден
особенно грубо, мелкие буквы дрожат.

## ГРАБЛИ, ОПЛАЧЕННЫЕ ЗАМЕРОМ

1. **`crop` высотой 1 падает на yuv420p** («height '0'»): хрома субсэмплится вдвое, 1/2 → 0.
   Лечится `format=gray` **до** кропа.
2. `-f rawvideo` требует явного `-pix_fmt`, иначе файл на 0 байт.
3. **`hwdownload` не работает без `format=` у libplacebo.** Связка: `libplacebo=...:format=yuv420p,hwdownload,format=yuv420p`.
4. libplacebo требует `-init_hw_device vulkan=vk -filter_hw_device vk` и `format=rgba,hwupload` на входе.
5. Запятые в выражениях `\,`, двоеточия `\:`.
6. `xfade=offset` от начала общего таймлайна.
7. Тонкая контрастная деталь + сильный даунскейл = алиасинг (может выдать себя за «поломанный пересемпл»).
