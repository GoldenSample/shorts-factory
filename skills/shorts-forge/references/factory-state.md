# АРХИТЕКТУРА ФАБРИКИ: СОСТОЯНИЯ, ИДЕМПОТЕНТНОСТЬ, ОЧЕРЕДЬ

Кладётся на прототип `C:\CLAUD\projects\alchim-channel\pipeline\` (ФСМ по 7 стадиям, `state.json`
на эпизод, стадии `s01_script`…`s07_publish`).

**Что в прототипе уже верно:** стадии — чистые функции `run(ep, cfg)`; артефакты на диске;
кэш дорогого медиа по `seg_hash`; резюмируемая заливка.
**Четыре дыры:** (1) `state.json` перезаписывается целиком — нет истории попыток, стоимости, причин;
(2) идемпотентность = «файл существует», а файл может быть **недописанным огрызком после Ctrl-C**;
(3) нет очереди — эпизод гонится по одному вручную; (4) `mark(stage,"ok")` не хранит **отпечаток
входов**, поэтому «готово» не отличить от «готово, но по старому скрипту».

**Хранилище: SQLite (WAL) — индекс состояния; байты остаются на диске.** БД никогда не хранит медиа,
только пути + sha256. Переносится в Postgres заменой типов.

## МОДЕЛЬ: ТРИ УРОВНЯ, НЕ СМЕШИВАТЬ

- **`episodes`** — бизнес-единица (что делаем, приоритет, окно, суммарная цена).
- **`steps`** — строка на (эпизод × стадия), *декларативное* состояние ФСМ. Её и лизует воркер.
- **`step_runs`** — строка на каждую попытку: сколько шло, чем упало, где трейс.

Статусы шага: `pending` → `ready` → `running` → `ok` | `partial` | `failed` | `needs_human` | `skipped` | `stale`.
- **`partial`** — шаг сделал часть юнитов (media: 8 из 10 сегментов). Ретрай доделывает **только
  недостающие**, счёт в `units_done/units_total`.
- **`stale`** — шаг `ok`, но `fingerprint` входов изменился (переписали скрипт → tts/align/assemble
  протухли, media по неизменённым сегментам — нет).
- **`needs_human`** — терминал, дальше только руки.

Артефакты: строка на каждый значимый выход, с `episode_id IS NULL` для общих — это и есть кэш реюза
между эпизодами и языками. `UNIQUE(content_hash) WHERE episode_id IS NULL` — одновременно замок и дедуп.

## ЧЕТЫРЕ ПРАВИЛА ИДЕМПОТЕНТНОСТИ

**1. Отпечаток входов вместо «файл есть».**
```python
def fingerprint(step, ep, cfg, upstream):
    payload = {"step": step, "code": STEP_VERSION[step],   # ручной bump при смене логики
               "cfg": {k: cfg[k] for k in CFG_KEYS[step]}, # только релевантные ключи!
               "up": sorted(a.sha256 for a in upstream)}
    return hashlib.sha256(json.dumps(payload, sort_keys=True, ensure_ascii=False).encode()).hexdigest()[:16]
```
⚑ Ключи перечислены **поимённо**, а не весь cfg: смена `qc.max_black_frac` не должна протухлять media.
Пропуск шага = `state='ok' AND fingerprint = fingerprint(...)`. Иначе → `stale`. Пересчёт делает
планировщик, не воркер.

**2. Артефакт публикуется атомарно, строка в БД — после файла.**
Все стадии пишут в `<name>.part`, затем `os.replace` (атомарно в пределах тома NTFS).
⚑ **Это чинит главную дыру прототипа:** недописанный `clip_<hash>.mp4` после Ctrl-C сейчас считается
кэш-попаданием и утекает в монтаж.

**3. Дорогой юнит-вызов = get-or-create под замком уникального индекса.**
```python
row = store.find_shared(content_hash)                    # 1) уже есть
if row and Path(row["path"]).exists(): return link(row)
if not store.reserve_shared(content_hash, ...):          # 2) INSERT state='reserved'
    return store.wait_shared(content_hash, timeout=900)  # другой воркер уже делает
make(tmp); publish_atomic(tmp, path)                     # внешний вызов ровно ОДИН раз
store.commit_shared(content_hash, path, cost)            # артефакт + usage в ОДНОЙ транзакции
```
`UNIQUE(resource, idem_key)` на `usage` гарантирует: повтор не удвоит счётчик квоты.

**4. Внешняя публикация — намерение ДО вызова.**
У YouTube нет ключа идемпотентности, строим сами:
1. До вызова — `INSERT INTO publications(state='intent', idem_key=sha256(...video_sha256))`.
   Конфликт по `UNIQUE(platform,idem_key)` = это видео уже заливалось, читаем строку.
2. Инициируем **resumable**-сессию, сразу сохраняем `session_uri` и `state='uploading'`.
3. На рестарте — **не новый `videos().insert`**, а запрос статуса сессии (`PUT` с
   `Content-Range: bytes */<size>`), докачка с `bytes_sent`. Сессия жива ~сутки; протухла (404/410) →
   новая под тем же `idem_key`.
4. Сверка после падения на неизвестном месте: `videos.list` по каналу за окно, матч по маркеру,
   зашитому в описание (`\n\n#ep:<slug>:<sha12>`). Нашли — `state='uploaded'`, ретрая нет.

⚑ **Единственная содержательная правка публикации:** `s07_publish` ретраит чанк внутри процесса —
это правильно, но `session_uri` **не переживает падение процесса**.

## ОЧЕРЕДЬ: ЛИМИТИРУЕМ РЕСУРСЫ, А НЕ ЭПИЗОДЫ

| ресурс | стадии | параллелизм | почему |
|---|---|---|---|
| `cpu` | script, align, qc | 3 | лёгкое |
| `grok` | media, tts-фолбэк | 2 | квота imagine, 429 при агрессии |
| `gpu` | tts, media-перелив (WAN), assemble | **1** | одна 5090, Qwen3 и ComfyUI не делят VRAM |
| `youtube` | publish | 1 | последовательная заливка |

WIP-лимит по эпизодам всё же нужен — **по диску: в полёте не больше 4-5**, проверка «свободно > 50 ГБ».

**Взятие работы — аренда (lease), не блокировка.** Транзакция IMMEDIATE: SELECT кандидата
(`state IN ('ready','partial','stale')`, ресурс совпал, `next_earliest <= now`, `attempt < max_attempts`,
предыдущий шаг `ok|skipped`, `not_before <= now`; ORDER BY `priority, seq`) → **CAS-захват**
(`UPDATE ... WHERE id=? AND state IN (...)`, `rowcount=0` = проиграл гонку).
TTL по классу: cpu 15 мин · grok 45 мин · gpu 4 ч · youtube 2 ч. Heartbeat раз в минуту.
**Reaper раз в 60с:** `running AND lease_until < now` → `ready`, `err_class='lease_lost'` —
память о сдохшем процессе.

**Разведение дорогого во времени:** `not_before` (окно генерации медиа ночью, когда 5090 свободна) ·
публикация не «сразу», а `publishAt` с шагом день/слот (растянуть по расписанию канала,
а не выкинуть пачкой — см. правило про нечеловеческий ритм) · `priority` 10 для пилота, 100 для потока.

## СТРАТЕГИЯ ПОВТОРОВ

| класс | триггеры | попыток | база/потолок | после исчерпания |
|---|---|---|---|---|
| `transient` | ConnectionError, timeout, 5xx | 5 | 20с / 10 мин | `needs_human` |
| `rate_limit` | 429, `quotaExceeded` | 8 | `Retry-After`, иначе 60с / 30 мин | суточная квота → `next_earliest` = начало след. окна, **попытка не тратится** |
| `gpu_busy` | CUDA OOM, ComfyUI 500 | 3 | 120с / 15 мин | понизить разрешение/batch |
| `auth` | 401, `invalid_grant` | **0** | — | сразу `needs_human` |
| `policy` | 400 content policy | 1 | — | переген с перефразом |
| `bad_input` | нет файла, битый JSON | **0** | — | `needs_human`, это баг данных |
| `partial` | часть сегментов без ассета | 3 | 60с | `needs_human` со списком idx |

`backoff = min(cap, base * 2**(attempt-1)) * random.uniform(0.5, 1.0)` — **jitter обязателен**.

- **Ретраить только идемпотентное.** `publish` не ретраится «с нуля» никогда: только докачка сессии
  или сверка по `remote_id`.
- **Дорогое не ретраить слепо:** у media/tts `max_attempts=3`, и ретрай обязан идти через
  `get_or_make` — иначе третья попытка = третья оплата.
- **Circuit breaker на ресурс:** 3 подряд `transient|rate_limit` по `grok` → пауза ресурса 15 мин,
  эпизоды на cpu/gpu продолжают идти. Без него один упавший API съедает все попытки всех эпизодов за минуту.
- **Терминал = `needs_human`, не удаление.**

## НАБЛЮДАЕМОСТЬ

Доска одним запросом (`v_board`): первый не-`ok` шаг каждого живого эпизода + попытки + units +
`err_class` + **`idle_min`** + цена + `lease_owner`, сортировка `needs_human` наверх.
Плюс: цена эпизода в двух валютах · цена по стадиям (сразу видно, что media жрёт 80%) ·
здоровье шагов (`fails`, `avg_s`, `max_s` по `step_runs`).

Логи — JSONL `logs/run.jsonl`, строка на событие. ⚠ Человекочитаемый трейс разносить
**по attempt** (`logs/<step>.<attempt>.log`) — сейчас `ep.log` дописывает в один файл и попытки слипаются.
Алерт: любой `needs_human` + `idle_min > 120` при непустой очереди → в телегу через мост КОНТУРа.

## Вариативность: готовых решений НЕТ

Ни одного зрелого проекта, который решает «сгенерировать 100 разных сценариев вместо 100 клонов».
Причина понятна: тема пограничная с политикой inauthentic content, всё живое в нише закрытое
(Opus Clip, Vidyo, Klap).

**Собирается самому из живых кусков:** persona/угол подачи как ось разнообразия → генерация K
кандидатов на слот → `semhash` против архива опубликованных → `text-dedup` против шаблонных хуков →
**отбор по максимальному расстоянию, а не по «лучшести»** → визуальный слой (CLIP-эмбеддинги кадров
против архива, чтобы обложки и первые 3 секунды не повторялись). Всё считается на локали бесплатно.
Идея persona-hub переносима бесплатно: генерировать сценарий не «по теме», а **«по теме от лица
персоны X»**, где персон тысячи — самый дешёвый источник настоящей вариативности, а не перефразирования.
