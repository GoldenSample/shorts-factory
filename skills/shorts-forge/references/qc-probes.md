# QC-ПРОБЫ: замеренные команды и регекспы

Всё прогнано на **ffmpeg 8.1.2** на активе 1080x1920/30fps/40s со вшитыми дефектами
(чёрное 10-13с, фриз 20-24с, тишина 5-8с). Форматы вывода — из реального прогона, не по памяти.

## ⚑ ЧЕТЫРЕ ГРАБЛИ, ЛОМАЮЩИЕ НАИВНЫЙ ГЕЙТ

1. **`freezedetect` считает чёрное фризом.** На активе выдал `freeze_start: 10` (это чёрный кусок)
   плюс настоящий фриз на 20. Без вычитания чёрных интервалов — двойной репорт на один дефект.
2. **Агрегаты `blur mean`/`block mean` отравляются NaN.** Один плоский кадр даёт `lavfi.blur=nan`,
   и итог становится `nan`. Читать **покадровую метаданную и брать медиану**, отбрасывая NaN.
3. **`blurdetect`/`blockdetect` контекстно-зависимы, шкала не абсолютная.** Резкий mandelbrot=6.68,
   резкий testsrc2=4.36; `block` на testsrc2=199 против 1.4 на нормальном h264. Порог не переносится
   между роликами — это тревога на регресс, а не приёмка.
4. **Дефолт `d=2`** у `blackdetect` и `silencedetect` пропускает почти все реальные дыры на 30-60с.
   Всегда задавать `d` явно.

## ПРОБЫ

### blackdetect — пропавшие куски
```bash
ffmpeg -hide_banner -nostats -i IN.mp4 -vf "blackdetect=d=0.5:pic_th=0.98:pix_th=0.10" -an -f null -
```
Вывод: `black_start:10 black_end:13 black_duration:3` (**двоеточие без пробела**)
```python
RE_BLACK = re.compile(r"black_start:(?P<s>[\d.]+)\s+black_end:(?P<e>[\d.]+)\s+black_duration:(?P<d>[\d.]+)")
```
**Фейл:** интервал ≥0.5с внутри `[0.3, duration-0.3]`. Затемнения на краях легитимны, середина нет.

### freezedetect — заглохшая генерация
```bash
ffmpeg -hide_banner -nostats -i IN.mp4 -vf "freezedetect=n=-60dB:d=1.0" -an -f null -
```
Формат **другой**: префикс `lavfi.` и пробел после двоеточия, три ключа **разными строками** —
собирать в интервалы по позиции в списке, не по одной строке.
```python
RE_FRZ_S = re.compile(r"freezedetect\.freeze_start:\s*(?P<v>[\d.]+)")
RE_FRZ_D = re.compile(r"freezedetect\.freeze_duration:\s*(?P<v>[\d.]+)")
RE_FRZ_E = re.compile(r"freezedetect\.freeze_end:\s*(?P<v>[\d.]+)")
```
**Обязательный постпроцесс:** вычесть чёрные интервалы. На стенде `[(10,13),(20,24.03)]` минус
`[(10,13)]` дало ровно один настоящий фриз. `n=-60dB` для идентичных кадров; при зерне поднимать до -50dB.
**Фейл:** фриз ≥1.0с после вычитания чёрного.

### silencedetect — отказ TTS
```bash
ffmpeg -hide_banner -nostats -i IN.mp4 -af "silencedetect=n=-45dB:d=0.6" -vn -f null -
```
Вывод: start и end **на разных строках**, end склеен с duration через `|`
```python
RE_SIL_S = re.compile(r"silence_start:\s*(?P<v>-?[\d.]+)")
RE_SIL_E = re.compile(r"silence_end:\s*(?P<e>[\d.]+)\s*\|\s*silence_duration:\s*(?P<d>[\d.]+)")
```
- `silence_start` бывает **отрицательным** (округление окна) → `max(0.0, s)`.
- Хвостовая тишина: ffmpeg флашит на EOF, `silence_end` печатается (проверено). Ветку «start без end» держать страховкой.
- `mono=false` по умолчанию — тишина только когда молчат ВСЕ каналы. «Одна колонка сдохла» ловится `mono=true`.

**Фейл (30-60с):** внутренняя тишина ≥1.5с · суммарно >25% длительности · тишина от 0.0 длиннее 0.5с
(обрезано начало фразы) · одна тишина на весь файл (TTS не отработал).

### blurdetect / blockdetect — замыленность и блочность
**Не** агрегатную строку, а покадрово с прореживанием (каждый 15-й кадр = 80 замеров на 40с, <1 сек):
```bash
ffmpeg -hide_banner -nostats -i IN.mp4 -vf "select='not(mod(n\,15))',blurdetect,metadata=mode=print:file=-" -an -f null -
```
⚠ `low`/`high` у `blurdetect` — пороги Canny в диапазоне **0-1** (дефолты 0.0588/0.1176).
`high=30` падает: `Value 30.000000 for parameter 'high' out of range [0 - 1]`.

Замеренная калибровка (mandelbrot 1080x1920, менялась только обработка):

| состояние | `lavfi.blur` |    | состояние | `lavfi.block` |
|---|---|---|---|---|
| резкий оригинал | 6.64-6.69 | | h264 crf 18 | 1.69-2.08 |
| gblur sigma=2 | 9.61-9.68 | | h264 crf 45 | 3.35-3.77 |
| апскейл 360p→1080p | 10.54-10.67 | | | |
| gblur sigma=6 | 18.92-19.11 | | | |

**Как ставить порог честно:** прогнать 10-20 заведомо годных своих роликов, взять медиану M,
тревога на `blur_median > 1.5·M` и `block_median > 1.8·M`. Стартовые абсолютные ограничители
`blur>11` / `block>3.0` — только до первой калибровки.

## ГРОМКОСТЬ: ДВУХПРОХОДНЫЙ loudnorm

**Проход 1, замер:**
```bash
ffmpeg -hide_banner -nostats -i IN.mp4 -af "loudnorm=I=-14:TP=-1.5:LRA=11:print_format=json" -vn -f null -
```
Значения приходят **строками**, приводить к float самому.
```python
RE_LNJSON = re.compile(r"\{[^{}]*\"input_i\"[^{}]*\}", re.S)
```

**Проход 2:** передать `measured_I/TP/LRA/thresh` + `offset`, `linear=true`.
- ⚠ **`aresample=48000` и `-ar 48000` обязательны:** loudnorm работает на 192 кГц и отдаёт наружу
  192 кГц (в логе `pcm_s16le, 192000 Hz`). Без ресемпла в контейнер уедет нестандартная частота.
- ⚠ **`linear=true` может молча выродиться в dynamic** (коррекция не влезла в лимиты). Ловить:
  `RE_LN_TYPE = re.compile(r"Normalization Type:\s*(?P<v>\w+)")`. Для речи терпимо, для музыки — варнинг.

**Ассерт снимать переизмерением готового файла, не прогнозом.** `output_i` из прохода 1 — предсказание;
AAC меняет пики.
```bash
ffmpeg -hide_banner -nostats -i OUT.mp4 -af "ebur128=peak=true:framelog=quiet" -vn -f null -
```
Парсить строго от подстроки `Summary:`: `Threshold:` встречается дважды, `I:` мелькает многократно.

| метрика | цель | ассерт | провал означает |
|---|---|---|---|
| Integrated | -14 LUFS | `abs(I+14) <= 1.0` | площадка перенормирует, ролик тише ленты |
| True Peak | -1.5 dBTP | `TP <= -1.2` | клиппинг после транскода |
| LRA | 11 LU | `LRA <= 13` | скачки громкости между сценами |
| `I == -inf` | — | мгновенный фейл | звука нет вообще |

Допуск ±1.0 LU (не ±0.5): AAC после нормализации сдвигает интеграл на десятые.

## СТРУКТУРНЫЕ АССЕРТЫ (ffprobe)

| проверка | правило | провал означает |
|---|---|---|
| длительность | `25.0 <= duration <= 65.0` | обрезка/недобор |
| разрешение | `(w,h) == (1080,1920)` строго | зальётся с полями, режется кроп |
| fps | `avg_frame_rate` ∈ {24,25,30,50,60} ±2% | VFR, рассинхрон |
| pix_fmt | `== yuv420p` | yuv444/p10 не играет на части устройств |
| аудиодорожка | есть поток `codec_type=="audio"` | немой ролик |
| расхождение A/V | `abs(audio.dur - format.dur) <= 0.5` | звук обрывается раньше картинки |

⚠ `avg_frame_rate` приходит дробью (`"30/1"`). Брать именно его, **не `r_frame_rate`** — второй у VFR врёт.

## СУБТИТРЫ

```python
RE_TC = re.compile(r"(\d{2}):(\d{2}):(\d{2})[,.](\d{3})\s*-->\s*(\d{2}):(\d{2}):(\d{2})[,.](\d{3})")
```
Перехлёст (`cues[i+1].start >= cues[i].end`) · выход за звук (`end <= audio_dur + 0.05`) ·
длительность ∈ [0.8, 7.0]с · строка ≤42 символов · строк ≤2.
Прогон на дефектном файле поймал ровно заложенное (47 символов, 11.5с, конец 45.0 при звуке 40.0, перехлёст 0.5с).

## ТЕМП РЕЧИ

Считать **не по полной длительности** — паузы занижают темп. Речевое время = длительность минус
детектированная тишина (`silencedetect` с чувствительным `d=0.35`):
```python
words = len(re.findall(r"[^\W\d_]+", text, re.UNICODE))   # ловит кириллицу, режет цифры
wps = words / (total_duration - total_silence)
```
Проверено: 10 слов, 10с всего, 3с тишины → speech=7.0, wps=1.428, wpm=85.7.

⚠ Полоса — **конвенция, не измерение**. Для русского шортса рабочая `2.0 ≤ wps ≤ 3.3` (120-200 wpm).
Русский плотнее английского по слогам на слово, английские таблички не переносить. Калибровать:
прогнать 10 своих роликов, звучащих нормально, взять медиану ±20%.
Дешёвый доп-ассерт: `total_silence/total_duration > 0.35` = рвано, дыры между фразами.

## ИЗВЛЕЧЕНИЕ КАДРОВ (для vision-яруса)

**Равномерно** (основной, всегда даёт ровно N), отступ 8% с краёв чтобы не поймать заставку и фейд:
```bash
ffmpeg -y -v error -ss 3.20 -i IN.mp4 -frames:v 1 -vf "scale=360:-2" -q:v 3 frame_01.jpg
```
`-ss` **перед** `-i` = поиск по ключевым кадрам, быстро. Таймкод в имени файла нужен: по нему видно,
какой дефект из проб какому кадру соответствует.

**По сценам** (`select='gt(scene,0.30)'`) — ⚠ замерено: вернул только 2 кадра из 6 на активе с малым
числом склеек. Порог не гарантирует N. Рабочая схема гибридная: сначала по сценам, недостающее добить
равномерным. Для непрерывной сцены (Ken Burns по картинке) сценовый не даст ничего, и это нормально.

`scale=360:-2` (не `-1`): гарантирует чётную высоту. JPEG `-q:v 3` ≈20 КБ на кадр — хватает и глазу,
и локальной vision-модели на 5090.

# ЯРУС 4: ЛОКАЛЬНАЯ VISION (замерено на 5090 + Ollama)

## ⛔ СНАЧАЛА МАТЕМАТИКА, ПОТОМ МОДЕЛЬ

⚑ **Если титр рисуем МЫ — vision не нужен вообще.** Обрезка краем это чистая геометрия по метрикам
глифов: 100% точность, 0 мс, проверка **до рендера**.

```python
def title_fits(text, font, xy, anchor, frame_wh, safe=0.05):
    W, H = frame_wh
    x0, y0, x1, y1 = ImageDraw.Draw(Image.new("L", (1,1))).textbbox(xy, text, font=font, anchor=anchor)
    mx, my = W*safe, H*safe
    over = {"left": max(0., mx-x0), "right": max(0., x1-(W-mx)),
            "top": max(0., my-y0), "bottom": max(0., y1-(H-my))}
    return {"hard_clip": x0 < 0 or y0 < 0 or x1 > W or y1 > H,   # физически рассечён
            "safe_violation": any(v > 0 for v in over.values()), # влез, но в safe-area
            "overflow_px": over}
```
Замер: сдвинутый титр → `hard_clip: True, overflow right: 671 px`. **Vision на том же кадре
промахнулся булевым полем.**

**Читаемость тоже считается детерминированно** — контраст WCAG цвета букв против фактического фона
**в ОРЕОЛЕ вокруг глифов**.
⚠ **Ловушка: сами пиксели букв брать нельзя** — в готовом кадре они уже цвета `fg` и дают контраст 1.0.
Брать `dilate(mask, 4+2*stroke) & ~dilate(mask, stroke)`, считать 5-й перцентиль отношений,
порог `p5 >= 3.0`.
Замер: белый титр на ровном фоне `p5 8.75 readable` · серый на пёстром `p5 1.05 not readable` —
совпало с вердиктом vision, но за 3 мс и без галлюцинаций.

⚠ **Чужой кадр детерминированно НЕ проверяется.** Замер эвристики «чернила у рамки»: обрезанный титр
`edge_ink 0.066`, чистый `0.0`, **но легальная графика у края 0.429**. Разделяющего порога нет —
метрика не отличает рассечённую букву от намеренно выходящего за край объекта.
**Годна только как вето / необходимое условие.**

**Модель нужна ровно когда:** кадр пришёл извне (генерация, стоки, чужой монтаж) и координат глифов
нет · текст «испечён» в сгенерированное изображение (вывески, плашки внутри кадра) · дефект
не описывается координатами вообще (абракадабра, плывущая анатомия, дубли объекта, «просто выглядит не так»).

## ⛔ БУЛЕВЫ ПОЛЯ У 7B ВРУТ СИСТЕМАТИЧЕСКИ

Замер на кадре с обрезанным титром:
```
"visible_text": "ОБРЕЗАННЫЙ З",           ← правда, модель ПРОЧЛА обрывок
"evidence": "Буква З обрезана справа"     ← правда
"glyph_severed_by_edge": false            ← ЛОЖЬ
```
То же на оверлапе: `evidence: "Надписи наезжают друг на друга"` при `text_overlap: false`.
**Под constrained decoding маленькая модель тянет булево в «дефекта нет».**

⚑ **Лечение: не спрашивать булевы. Спрашивать МАССИВ найденных дефектов** — перечисление
положительного вместо отрицания. После замены схемы те же кадры стали размечаться верно.

⚑ **Порядок полей в JSON-схеме = порядок рассуждения** (Ollama генерирует строго по порядку свойств).
Транскрипт текста **первым**, вердикт-коды после, severity последним — тогда модель сначала читает
пиксели, потом судит по прочитанному. Плюс правило в промпте: **«код ставь, только если ты назвал
это в what_is_wrong»** — связывает код с прозой и обрывает голое угадывание.

`format` со схемой работает с vision без оговорок: JSON валиден **36/36 прогонов**.

## МОДЕЛЬ И ПОДАЧА

**Брать `qwen3-vl:8b-instruct`** (Apache-2.0, 6 ГБ, лидер по OCR+grounding среди мелких; нужна
Ollama ≥0.12.7). Арбитр для спорных — `qwen3-vl:32b-instruct-q4_K_M` (**18.5 ГБ VRAM** замерено).
MiniCPM-V лучше по OpenCompass, но лицензия требует регистрации — лишний юридический хвост.
⛔ **`huihui_ai/*` и прочие community-абляции ЛОМАЮТ vision-проектор**: замер дал 3× HTTP 500,
потом таймаут 600с при GPU 0%. Брать официальные теги библиотеки.

**Кадры:** 12 равномерных + до 24 по сменам сцен (`select='gt(scene,0.35)'`), дедуп dHash
(Хэмминг ≤6) → обычно 15-25 на ролик. **Гибрид обязателен:** решётка ловит длинные планы,
сцены ловят титры и склейки — а именно там живёт обрезка текста (титр живёт 2с, решётка его пропустит).
**Ужимать до 1024 px по длинной стороне, JPEG q90:** ниже 768 теряется мелкий текст и модель начинает
выдумывать, выше 1024 — рост токенов без прироста. Отдавать base64 в `images`, **не URL**
(URL-загрузка даёт свой ресайз и деградацию).

## ПОРОГИ И АНТИ-ГАЛЛЮЦИНАЦИИ

Замер на 6 кадрах с известным ground truth: **5/6, ноль ложных срабатываний на чистом кадре.**
Оба промаха — по несрочным дефектам (чёрный кадр поймала дешёвая проба, оверлап пропущен);
критичное (обрезка) поймано.

- **fail кадра** — HARD-дефект (рассечённый глиф, абракадабра, пустота, плывущая анатомия) или severity 3.
- **flag** — остальное + мыло по `lapvar < 40`.
- **REJECT ролика** — ≥2 fail ИЛИ `bad_share ≥ 0.34` (fail=1, flag=0.5).
  ⚑ **Один fail = REVIEW, не автоотбраковка:** один плохой кадр из 20 чаще ложняк, чем брак ролика.

Против ложных срабатываний, по эффективности:
1. ⚑ **Вето дешёвой пробой (3 мс).** Vision заявил обрезку → требуем `edge_ink ≥ 0.01`: если у рамки
   нет контраста, рассекать нечего. То же для `frame_empty`. **Снимает основной класс галлюцинаций.**
2. «Сомневаешься — дефекта нет» + связка кода с прозой (см. выше).
3. **Мажоритарка 3 прогонов** (seed 7/8/9). ⚠ Нужна, потому что **при `temperature: 0` повторы
   всё равно не бит-в-бит**: тот же кадр в двух прогонах дал severity 2 и 1.
   **Пороги на одном прогоне не калибруются.**
4. **Белый список сцен:** намеренно расфокусированный фон и минимализм валят `lapvar` и дают
   `subject_in_corner` — если такие планы в стиле ролика, переводить эти коды в «только пометить».

⚠ **Операционное:** ставить `OLLAMA_MAX_LOADED_MODELS=1` и `keep_alive` — иначе 27B и 7B не уживаются
в 32 ГБ и запросы виснут в очереди на выгрузку.

**Маршрут яруса:** свои титры — только математика (vision не звать, ноль ложняков и ноль секунд);
VLM — только на кадры с чужим или испечённым контентом, с дешёвыми пробами в роли вето.
