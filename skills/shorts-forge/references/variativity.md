# ДВИЖОК ВАРИАТИВНОСТИ (ядро фабрики)

Не «пиши разнообразно», а счётные ограничения. Всё ниже — из дословного текста политики
плюс инженерные следствия. Проектные пороги помечены отдельно: они калибруются (§5), не выдуманы.

## ЧТО СКАЗАНО ДОСЛОВНО (первоисточник support.google.com/youtube/answer/1311392)

НЕ монетизируется: «minimal variation across videos»; «характеры в одной ситуации снова и снова
с тем же исходом (highly similar storyline template)»; слайдшоу и бегущий текст без нарратива;
**«AI-generated content made with generic or unoriginal templates giving the impression of mass
production without adding the creator's original, authentic insights or perspective»**.

МОНЕТИЗИРУЕТСЯ (явные исключения, ими и пользоваться): **«Same intro and outro for your videos,
but the bulk of your content is different»**; серия с общими персонажами или обзорами продуктов,
**«in which each video has a distinct storyline, focus, or concept»**.

Отдельный жёсткий гейт: канал неeligible, если ИИ-персона подаётся «as a human expert providing
advice» по темам **health, legal, finance, politics**.

Что смотрит ревьюер (официально): главная тема, самые просматриваемые, **самые новые**,
наибольшая доля времени просмотра, метаданные (заголовки, тумбы, описания), раздел About.

## ЧЕТЫРЕ СЛЕДСТВИЯ ДЛЯ АРХИТЕКТУРЫ

1. **Оконность.** Единица оценки — «несколько роликов подряд», а не корпус. Метрика обязана быть
   оконной: максимум попарной похожести внутри окна из w подряд идущих. Корпус, разложенный
   блоками (20 роликов стиля A, потом 20 стиля B), проваливает тест при высокой общей энтропии.
2. **Три среза, не один.** Ревью сэмплит «новейшие» и «самые просматриваемые» — множества почти
   не пересекаются. Гейт считать отдельно по: последние 30, топ-30 по просмотрам, топ-30 по watch time.
   Ролик может быть уникален среди соседей по дате и клоном другого хита.
3. **Интро/аутро/один голос РАЗРЕШЕНЫ явно.** Не тратить на них бюджет вариативности и не бояться
   единого голоса канала. «Наберём 10 голосов, чтобы не спалиться» лечит не ту болезнь.
4. **Оригинальность — отдельная ось.** 100 попарно непохожих пересказов новостей всё равно
   попадают под пункт. См. §4.

## МОЩНОСТЬ ОСЕЙ: ОТКУДА БЕРЁТСЯ ЧИСЛО

Ноль повторов внутри окна из w подряд достижим **тогда и только тогда, когда уровней k ≥ w**
(нужен зазор g = w−1, а выбирать есть из чего только при k ≥ w).

Проектная точка **w = 8** → салиентные оси минимум **8 уровней**, несалиентные 4-5.
w — наше допущение (запас над «several» ≈ 3-7), а не цифра из политики.

```python
def mingap_schedule(levels, n, gap, rng, weights=None):
    out, cooldown = [], []
    for _ in range(n):
        pool = [l for l in levels if l not in cooldown[-gap:]] or list(levels)
        pick = rng.choices(pool, weights=[weights[l] for l in pool] if weights else None)[0]
        out.append(pick); cooldown.append(pick)
    return out
```

## ГЛОБАЛЬНАЯ ГАРАНТИЯ: ОРТОГОНАЛЬНЫЙ МАССИВ

Min-gap не мешает роликам #7 и #63 быть близнецами — а если оба в топе, ревьюер видит клонов.
Нужен план с гарантированным минимальным расстоянием Хэмминга по всему корпусу.

OA силы 2 на GF(q), q простое: прогон индексируется парой (x,y), фактор f даёт `A_f(x,y)=(y+f·x) mod q`.
Свойство: **два различных прогона совпадают ровно по ОДНОМУ фактору из q+1.**
(Если x₁=x₂, то из y₁+f·x₁=y₂+f·x₂ следует y₁=y₂ — тот же прогон. Значит x₁≠x₂ и f=(y₂−y₁)/(x₁−x₂) однозначен.)

**q=11: 121 прогон, до 12 осей по 11 уровней, любые два ролика совпадают ровно по одной оси из двенадцати.**
Математическая гарантия против «feel interchangeable», покрывает 100 роликов с запасом.

```python
def oa_prime(q, n_factors):           # q простое; n_factors <= q+1
    runs = []
    for x in range(q):
        for y in range(q):
            row = [(y + f*x) % q for f in range(min(n_factors, q))]
            if n_factors > q: row.append(x)
            runs.append(row)
    return runs                        # q*q прогонов
```

**Порядок сборки: OA даёт глобально разнесённые конфиги → min-gap переставляет их во времени.**
Перестановка не меняет попарные расстояния, обе гарантии живут вместе.
Если оси связаны (формат «сравнение» тянет сплит-экран и таблицу) — вместо OA брать CP-SAT
(ortools): максимизировать минимальное попарное Хэммингово при запретах совместимости.

⚠ **Ловушка: комбинаторная различность ≠ воспринимаемая.** OA гарантирует, что «музыка №3» и
«музыка №7» — разные ID, а не что они звучат по-разному. По каждой оси нужен **пол разделимости**:
попарное расстояние эталонных рендеров уровней в том же эмбеддинг-пространстве. Уровни, севшие
ближе порога, схлопываются — мощность оси честно уменьшается. Без этого все цифры фиктивны.

**Ось 5 критична:** варьировать промпты внутри одной модели НЕДОСТАТОЧНО — фиксированный сэмплер
даёт узнаваемый «домашний вид» на уровне пикселей, это и есть generic template. Тракты:
WAN i2v локально · grok imagine · сток · запись экрана · архив с параллаксом · графики из данных ·
типографика без изображений · схемы · своя b-roll библиотека · композит. **Доля одного тракта ≤30%.**

**Ось 6:** идентичность голоса нарушением НЕ является (серийность разрешена явно). Нарушение —
одинаковый просодический шаблон. DTW между контурами F0 первых предложений: если все ложатся
в один контур, ролики звучат одинаково, что бы ни шло дальше.

**Ось 10:** прожжённый субтитр занимает центр экрана весь ролик — единый жёлто-поп-караоке
на ста роликах читается как шаблон раньше всего остального.

## СЧЁТНЫЕ МЕТРИКИ (считаются кодом на локали, LLM не нужна)

- **Джаккар по 3-граммам первых 12 слов** ≤ 0.20 — зона открытия выдаёт шаблон сильнее всего.
- Левенштейн по последовательностям типов битов: между форматами ≥0.6, **внутри формата ≥0.35**
  (второе важнее: жёсткая грамматика делает все «опровержения» одинаковыми).
- Длина: CV ≥ 0.35; ни одно 5-сек ведро > 25%; **уникальных значений длительности ≥ 0.6·N**
  (40 роликов ровно по 59.0с = отпечаток рендер-шаблона, видимый без всякого ИИ).
- Темп: std WPS по предложениям ≥0.5; **энтропия гистограммы интервалов между склейками ≥0.7**
  (склейка ровно каждые 2.5с даёт энтропию около нуля).
- Визуал: CLIP-эмбеддинги кадров каждые 2с → центроид ролика → попарный косинус, максимум в окне.
- Заголовки: макс. Джаккар по 3-граммам ≤0.2; CV длины ≥0.25.
- self-BLEU-4 и distinct-1/2/3 по корпусу сценариев.

### Единое число: Vendi Score

`VS = exp(−Σ λᵢ log λᵢ)` по собственным значениям нормированной матрицы похожести K/n —
**эффективное число различных элементов**. VS=6 на 100 роликах = «шесть роликов в ста экземплярах».

```python
import numpy as np
def vendi(K):                     # K: n x n PSD, диагональ = 1
    ev = np.linalg.eigvalsh(K/len(K)); ev = ev[ev > 1e-12]
    return float(np.exp(-(ev*np.log(ev)).sum()))
```

Считать отдельно по сценариям / визуалу / аудио / темам / метаданным — и по каждому из трёх срезов.

## ГЕЙТЫ КОНВЕЙЕРА

| Гейт | Когда | Считает | При провале |
|---|---|---|---|
| A | до генерации | коллизии конфига в окне, мин. Хэмминг к корпусу | переназначить конфиг |
| B | после сценария | novelty_ratio, unsupported, Левенштейн битов, Джаккар открытий | вернуть на переписывание с указанием оси |

Все замеры — в `variant_ledger.sqlite` (конфиг-вектор + метрики + id). Min-gap читает ту же таблицу.
**Без реестра оконные метрики не считаются в принципе.**

Порядок подъёма: реестр → гейт B (дешевле всех, ловит больше всех) → OA+min-gap → гейт E
(дёшев, цена провала максимальна) → гейт C → калибровка → гейт D и дашборд VS.

## §5 КАЛИБРОВКА ПОРОГОВ (иначе цифры = тот же фолклор)

Любое «косинус ≤ 0.75» из головы — выдумка. Честный метод:
1. Собрать референс-корпус: 10-20 **живых человеческих** каналов той же ниши, по 50-100 роликов,
   монетизированных и не задетых волнами.
2. Прогнать по ним **тот же самый код метрик**.
3. 25-й перцентиль их разнообразия = пол для нас, медиана = цель.
4. Пересчитывать раз в квартал.

⚠ **Честная граница:** всё это оптимизирует измеримый ПРОКСИ шаблонности. Совпадение прокси
с реальным классификатором YouTube не гарантировано и снаружи не проверяемо. Детектор не
опубликован — любые «похожесть выше 0.8 = бан» выдуманы.

## ⚠ ФОЛКЛОР (первоисточника нет)

- «Первые 3 секунды решают всё» — оптимизация ретеншна, к тексту политики отношения не имеет.
- «Публикуйте в случайное время» — правдоподобно, но каденции в политике нет. Проходит как вывод.
- «Нужно много голосов, иначе забанят» — **прямо противоречит** явному разрешению серийности.
- «Раскрытие ИИ убивает охват» — опровергается: бьёт именно НЕраскрытие реалистичного синтетического.
- «X роликов в день = бан» — числового порога в политике нет, оценка качественная и на уровне канала.
