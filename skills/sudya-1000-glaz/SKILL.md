# Судья «тысяча глаз»: Qwen3.5-122B-A10B дома

Модель: `Qwen/Qwen3.5-122B-A10B` (Apache 2.0, 04.2026), в Ollama тег `qwen3.5:122b` (Q4, 75,8 ГБ),
у нас заведена как **`sudya`** с контекстом 32k. Живёт на домашней 5090 (10.77.0.2:11434 через хаб
<VPS_IP>; с сервера сайта — труба `127.0.0.1:21434`, см. `pc-store/zavod/cron-zavod.sh`).
Активных параметров 10B → эксперты в ОЗУ, внимание на карте. Это **пакетный ночной судья**, не чат.

## Как звать

```python
# родной API — точные счётчики скорости, схема ответа принудительно
POST http://10.77.0.2:11434/api/chat
{"model": "sudya", "stream": false, "keep_alive": "30m",
 "think": true,                       # выключать только на тривиальных линзах
 "format": <JSON-схема ответа>,       # Ollama держит выход в схеме грамматикой
 "options": {"temperature": 0.7, "top_p": 0.8, "top_k": 20, "presence_penalty": 1.5, "num_ctx": 32768},
 "messages": [{"role":"system","content": ...}, {"role":"user","content": ...}]}
```

- Через OpenAI-совместимый `/v1/chat/completions` (так ходит завод) — `response_format json_object` работает, `num_ctx` берётся из модели `sudya`, поэтому она и заведена с 32k: у голого тега 4k, и статья с базой фактов молча режется.
- Сэмплинг по README Qwen3.5: **без размышления** `temperature 0.7, top_p 0.8, top_k 20, presence_penalty 1.5`; **с размышлением** `temperature 1.0, top_p 0.95, top_k 20, presence_penalty 1.5`. Ниже 0.7 модель начинает повторяться — не «занижать для точности», точность даёт линза, не температура.
- Мягких переключателей `/think` `/no_think` у 3.5 нет — только параметр `think` (Ollama) или `enable_thinking`.
- `keep_alive`: 30m на время прогона, потом отпустить — 76 ГБ мешают видеостеку. Первый вызов после простоя платит разворачивание (см. замеры).
- Контекст 32k хватает на статью + базу фактов + схему; 262k нативных — но каждые 10k контекста это память и время, не расширять без нужды.

## Принцип «тысячи глаз»

Один составной вопрос «проверь статью» даёт один размытый ответ. Тысяча глаз — это **много узких вопросов**, каждый с одним критерием, одним форматом ответа и обязательной **уликой-цитатой** из текста. Слепые пятна одной линзы закрывают другие; слияние делает код, не модель.

Правило из калибровки судей (память `model-judge-calibration`): узкий вопрос вместо составного, **признак вместо запрета** («найди все числа и для каждого укажи строку базы фактов» лучше, чем «не пропусти выдуманных чисел»), пережатый гейт вреден так же, как дырявый.

### Линзы для завода (статья / ответ мастера / разбор новости)

| # | Линза | Что возвращает |
|---|---|---|
| 1 | **Числа** | каждое число текста → цитата → строка базы фактов или `нет в базе` |
| 2 | **Обещания** | фразы «гарантируем», «всегда», «любой», «лучший» → цитата |
| 3 | **Машинные обороты** | вводные из списка BANNED + свои находки → цитата |
| 4 | **Реквизиты и юрлицо** | ООО/ИП/ИНН/адрес не из базы → цитата |
| 5 | **Цены и бонусы** | любая цена заказной сборки, скидка, «бонус клиенту», имя клиента → цитата (правило GSPC: цены не публикуем) |
| 6 | **Факты о железе** | утверждения о моделях, частотах, ваттах → цитата → подтверждено базой / общеизвестно / сомнительно |
| 7 | **Логика** | противоречия внутри текста (в одном абзаце 3 года, в другом 2) |
| 8 | **Заголовок ↔ тело** | обещание заголовка и лида выполнено? чем именно |
| 9 | **FAQ** | каждый вопрос со знаком «?», ответ отвечает на вопрос, а не рядом |
| 10 | **Структура** | длина разделов, списки, markdown, повторы заголовков |
| 11 | **Голос** | «мы» мастерской без «вы, дорогие читатели», без канцелярита и без сленга |
| 12 | **Разбор новости** | источник в `sources` с рабочей ссылкой; заголовок не копия чужого; цифры вендора только со ссылкой |
| 13 | **Коммерческий выход** | последний раздел ведёт в витрину / услугу, а не в пустоту |
| 14 | **Что пропустили** | «какой вопрос читатель задаст после этого текста и не получит ответа» |

Схема ответа каждой линзы одна: `{"items":[{"quote":"...", "verdict":"ok|fix|reject", "why":"..."}], "summary":"..."}`. Без цитаты претензия не принимается кодом.

### Слияние

- Любой `reject` в линзах 1, 4, 5, 12 → материал не выходит.
- `fix` → один проход исправления той же моделью с перечнем цитат, затем повтор **только упавших линз**.
- Две линзы спорят → не усреднять, а третий узкий вопрос ровно по спорной цитате.
- Итоговый вердикт собирает код, модель итог не выносит.

## Каркас промпта линзы

```
[system] Ты редактор мастерской Golden Sample PCs. Отвечаешь только JSON по схеме, по-русски, без вступлений.
Единственный источник цифр — БАЗА ФАКТОВ ниже. Чего нет в базе, того нет в тексте.

[user]
ЛИНЗА: <одно предложение — что ищем>
КАК: <признак, по которому опознать; 1–3 примера из этого же домена>
БАЗА ФАКТОВ:
<facts.md, целиком>
ТЕКСТ:
<материал JSON или текст>
ФОРМАТ: <схема>. Для каждой находки — точная цитата из ТЕКСТА.
```

Что важно:
- **База фактов раньше текста**: модель читает эталон до проверяемого.
- Примеры признака — из нашего домена (цена сборки, срок теста, гарантия), не абстрактные.
- Не просить «будь внимателен» — просить **перечислить все N** (все числа, все вводные). Перечисление и есть внимательность.
- Русский в system и user; модель на русском стабильна, но при presence_penalty > 1.5 начинает мешать языки — не поднимать.
- Одна линза — один вызов. Не склеивать линзы ради экономии: у нас бесплатный ночной GPU, экономить нечего.

## Скорость и память (ЗАМЕРЕНО 22.09.2026, `judge_test.py`)

- Закачка 75,8 ГБ дома: 55–130 МБ/с, 30 минут чистой передачи (с двумя остановками).
- **Разворачивание в память: 49,4 с** холодным стартом с диска E:; тёплый — 0,2 с.
- **Раскладка**: 76,5 ГБ всего, из них **29,3 на карте, 47,3 в ОЗУ**. Системная ОЗУ дома: 5,1 → 54,0 ГБ (+49). На 32 ГБ это не запускается вовсе.
- **Скорость**: промпт 320–420 ток/с, ответ **33 ток/с** — лучше расчётных 12–16, потому что бóльшая часть весов легла на карту.
- **Стоимость одного вызова с размышлением**: 121–125 с при 4–6k токенов промпта и ~110–155 токенах JSON-ответа. Счётчики Ollama показывают только видимые токены; ~95 с уходят на невидимое размышление (~3 000 токенов). Линза с `think: false` ≈ 25 с.
- 14 линз × 2 мин ≈ 28 минут на материал с размышлением, ≈ 6 минут без. Для завода на 3 материала в день — с запасом; думать включать на линзах 1, 6, 7, 14, остальным хватит без.
- **Качество на тесте**: обе подложенные ошибки (цена 15 000 не из базы, «давайте разберёмся») пойманы холодным прогоном с точной ссылкой на базу («бесплатно при покупке у нас или от 9 990 ₽»); тёплый прогон дополнительно поймал «3–5 дней», которых в базе нет. Второй прогон строже первого — ещё довод за несколько узких проходов.

## Грабли

- `WanVideo*`/ComfyUI и судья делят 96 ГБ: 76 ГБ судьи + 55 ГБ видеостека не помещаются. Ночью завод, днём ролики; `keep_alive` не «-1».
- Диск дома E: — модели Ollama; 22.09 диск был полон, снесён 235B. Перед новыми весами считать место.
- `format` со схемой + `think: true`: размышление идёт до JSON, в ответе его нет; на тривиальных линзах (структура, FAQ) `think: false` вдвое быстрее.
- Abliterated-сборки (как лежащий Qwen3.6 35B) режут качество суждений — судья только на официальных весах.
- Завод: `ZAVOD_JUDGE_BASE_URL` + `ZAVOD_JUDGE_MODEL`; крон сам проверяет, отвечает ли дом, иначе судит подписка. Писатель остаётся Grok — квота подписки уходит на текст, не на проверку.
