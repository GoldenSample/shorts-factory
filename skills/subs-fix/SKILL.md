# Субтитры без ручных правок

Автоматическая расшифровка (Premiere «Речь в текст», CapCut и т.п.) почти всегда требует
доработки: ошибки распознавания, слова-паразиты, длинные блоки, странные переносы.
Задача скила — сделать всю эту работу за один проход, чтобы пользователю осталось только
импортировать готовый файл обратно в редактор.

## Шаг 1. Получить субтитры

Рабочий формат — SRT. Откуда он берётся:

- **Пользователь дал .srt** — работаем с ним.
- **Пользователь дал проект Premiere (.prproj) или сказал «в проекте»** — сам файл проекта
  НЕ трогать: это gzip-XML с недокументированной структурой, текст субтитров в нём не лежит
  открытым текстом, а правка файла может убить проект. Вместо этого попроси экспортировать
  SRT (или сделай это за пользователя, если доступно управление компьютером и Premiere
  открыт) — точные шаги в [references/premiere-workflow.md](references/premiere-workflow.md).
- **Проект CapCut** — там субтитры доступны напрямую в `draft_content.json`;
  см. [references/capcut-draft-format.md](references/capcut-draft-format.md).
- Путь не дан — поищи свежие `.srt` в Downloads/Desktop/рабочей папке.
  Спрашивай пользователя только если поиск ничего не дал.

Оригинал никогда не перезаписывай: результат сохраняй как `<имя>_fixed.srt` рядом с исходником.

## Шаг 2. Понять контекст

Прочитай субтитры целиком до любых правок. Определи: тему видео, имена, бренды, термины,
жаргон. Ошибки распознавания исправляются по смыслу — «примьер» в видео про монтаж это
«Premiere», «клод» в видео про нейросети это «Claude». Без понимания контекста правка
превращается в угадывание.

## Шаг 3. Три прохода правки

Выполняй именно в этом порядке: сначала чинится текст, потом убирается мусор, и только потом
режется на блоки — иначе разбивка развалится после удаления слов.

### Проход 1 — ошибки распознавания

- Неправильно услышанные слова: восстанавливай по контексту (названия, термины, англицизмы).
- Склейки и разрывы: «в ручную» → «вручную», «не смотря на» → «несмотря на» (где это предлог).
- Повторы распознавания: «и и», «что что» — убирай дубль.
- Регистр: предложение начинается с заглавной; блок, продолжающий фразу, — со строчной.
- Пунктуация в стиле субтитров: точки в конце блоков убирай, `?` `!` `…` сохраняй,
  запятые внутри блока ставь только там, где без них читается неправильно.
  Если пользователь просит «полную» пунктуацию — ставь всё по правилам языка.

### Проход 2 — слова-паразиты

Типовые для русской устной речи: `ну`, `вот`, `короче`, `как бы`, `типа`, `это самое`,
`в общем`, `так сказать`, `значит`, `собственно`, `по сути`, `слушай(те)`, `смотри(те)`,
междометия `э-э`, `а-а`, `м-м`, `ммм`.

Главное правило: **убирай слово только если после удаления смысл фразы не меняется**.
Те же слова бывают значимыми:

- «сделал описание **короче**» — прилагательное, оставить;
- «**значит** ли это, что…» — глагол, оставить;
- «**смотри** на график» — реальный императив, оставить;
- «ну **вот** такой результат» — «ну» убрать, «вот» здесь указательное — по ситуации.

После удаления паразита проверь стык: не осталось ли двойных пробелов, висячих запятых,
строчной буквы в начале предложения.

### Проход 3 — разбивка на короткие блоки

Длинный блок на экране нечитаем. Целевой формат (если пользователь не задал свой):
**1–2 строки, до ~28 символов на строку** — под вертикальное видео. Для горизонтального
(YouTube 16:9) можно до 42 символов на строку.

Правила разбивки:

- Резать по границам фраз: пунктуация, союзы, смена мысли. Никогда — посреди слова.
- Не отрывать предлоги, союзы и частицы от следующего слова («и», «не», «в», «на»
  в конце строки — плохо).
- Тайминг при делении блока распределяй **пропорционально длине текста** частей:
  блок 4 с с текстом 60/30 символов → 2.7 с и 1.3 с.
- Минимальная длительность блока — 0.8 с; если пропорция даёт меньше, отдай минимум
  и сократи соседа.
- Начало первого блока и конец последнего не двигай — синхронизация с речью важнее
  красоты. Блоки не должны накладываться (конец предыдущего ≤ начало следующего).
- Слишком короткие соседние блоки (< 0.7 с, пара слов) можно объединить, если суммарный
  текст влезает в формат.

Если пользователь явно просит «тайминги не трогать» — работай только с текстом внутри
существующих блоков: не разбивай, не объединяй, не сдвигай ни одну метку времени.

## Шаг 4. Сохранить и проверить

1. Сохрани результат в UTF-8: `<имя>_fixed.srt` (нумерация блоков с 1, сквозная).
2. Прогони валидатор:
   ```
   python scripts/srt_check.py <файл_fixed.srt> --max-chars 28 --max-lines 2
   ```
   Он ловит структурные проблемы: битые таймкоды, наложения, слишком короткие/длинные
   блоки, превышение длины строк, двойные пробелы. Ошибки исправь и прогони снова.
   Если Python недоступен — проверь те же пункты вручную по списку из скрипта.
3. Перечитай итоговый текст целиком ещё раз как редактор: смысл нигде не потерялся?
   Паразит, который был значимым словом, не удалён?

## Шаг 5. Отчёт пользователю

Коротко и по делу:

- путь к готовому файлу;
- статистика: было блоков → стало, сколько ошибок исправлено, сколько паразитов убрано;
- 2–3 примера «до → после» (самые показательные);
- как импортировать обратно — для Premiere шаги из
  [references/premiere-workflow.md](references/premiere-workflow.md) (Файл → Импорт →
  перетащить на таймлайн в начало эпизода → применить стиль дорожки, старую дорожку
  отключить), для CapCut: Текст → Локальные субтитры → импорт SRT.

**Пример отчёта:**

```
Готово: interview_fixed.srt

42 блока → 57 (длинные разбил под вертикальный формат)
Исправлено 11 ошибок распознавания, убрано 19 слов-паразитов

Примеры:
«ну короче я в ручную правил сабы в примьере»
→ «Я вручную правил сабы в Premiere»

Импорт: Файл → Импорт → interview_fixed.srt, перетащи на таймлайн
в начало эпизода, задай стиль дорожки, старую дорожку субтитров отключи.
```
