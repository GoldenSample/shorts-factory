## 6. Ключ сообщества (уровень 0: гигиена и истории)

- [ ] Управление -> Дополнительно -> Работа с API -> Ключи доступа -> Создать ключ. Права: управление, фотографии, истории, документы (+ сообщения, когда будет пересыльщик). Подтверждение в приложении ВК или по СМС - только владелец.
- [ ] Ключ сразу на VPS: `/opt/shorts/vk.env`, строка `VK_COMMUNITY_TOKEN=...`, права файла 600. В чат, git и на локальную машину ключ не попадает. Клод дальше проверит его `vk_api.py` (ожидаемая маска без сообщений 393221).

## 7. Ключ админа (уровень 2: без рук)

1. [ ] Вход в VK Бизнес ID (id.vk.com/business), создать приложение типа Web. Профиль бизнеса подтвердить в течение 60 дней после создания первого приложения, иначе блокировка. До подтверждения - 10 000 вызовов API в месяц, после - 100 млн.
2. [ ] Письмо в devsupport@corp.vk.com: `templates/devsupport-letter.md`. Просить wall, photos, video (и stats). В списке расширенных прав wall не значится - просить явно.
3. [ ] После одобрения - первичная авторизация админа в браузере (authcode + PKCE, VK ID). Клод готовит адрес авторизации и принимает код на VPS; пара access/refresh и device_id ложатся в `/opt/shorts/vk_user.json` (600). У админа должна быть включена двухфакторная защита (иначе ошибка 704 на загрузке видео).
4. [ ] В `vk.env`: `VK_CLIENT_ID=...`, `VK_AUTO=1`. С этого момента завод ставит посты в отложку сам.

Проверка отчётом: Habr q/1398200 (2025) - `wall` через authcode+PKCE выдали, `wall photos` - нет. Если выдадут только `wall`, завод может постить текст; посты с видео и фото остаются пакетами до расширения прав.
