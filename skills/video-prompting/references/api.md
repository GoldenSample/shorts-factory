## 1. Официальная дока xAI

Источник: https://docs.x.ai/developers/model-capabilities/video/generation (сверено 2026-09-10).

### 1.1. Эндпоинты

ЗАМЕРЕНО (дока):
- `POST https://api.x.ai/v1/videos/generations` - text-to-video, image-to-video, reference-to-video.
- `POST https://api.x.ai/v1/videos/edits` - правка готового видео (нужен `video`).
- `POST https://api.x.ai/v1/videos/extensions` - продление видео (нужен `video`).
- `GET https://api.x.ai/v1/videos/{request_id}` - статус и результат.

Схема всегда двухшаговая: POST возвращает `request_id`, дальше поллинг GET. Синхронного ответа с файлом нет.

ЗАМЕРЕНО (дока): статусы `pending`, `done`, `expired`, `failed`.
Наш `gen_media.py` дополнительно ловит `error` и `cancelled` - в доке их нет, это защитный код (не проверяли, приходят ли они реально).

### 1.2. Модели и цена

ЗАМЕРЕНО (https://docs.x.ai/docs/models):

| модель | цена |
|---|---|
| `grok-imagine-video` (классика) | 0.050 usd за секунду |
| `grok-imagine-video-1.5` | 0.080 usd за секунду |
| `grok-imagine-image` | 0.02 usd за кадр |
| `grok-imagine-image-2.0` | 0.04 usd за кадр |
| `grok-imagine-image-quality` | 0.05 usd за кадр |

Цена в доке дана ЗА СЕКУНДУ и не разбита по разрешению: 480p, 720p и 1080p стоят одинаково при равной длительности. Это важнее, чем кажется - см. раздел 4.
Рекомендация самой доки: для видео брать `grok-imagine-video-1.5`, для картинок `grok-imagine-image-2.0`.

### 1.4. Полная схема тела запроса (REST-справочник)

Источник: https://docs.x.ai/developers/rest-api-reference/inference/videos (сверено 2026-09-10). Этот справочник точнее обзорной страницы - тут видно типы полей.

| поле | тип | обязательно | значения / примечание |
|---|---|---|---|
| `model` | string | - | идентификатор модели |
| `prompt` | string | да (для t2v) | текст |
| `aspect_ratio` | string | нет | 7 значений, см. выше |
| `duration` | integer | нет | **[1-15], умолчание 8** |
| `resolution` | string | нет | `480p` / `720p` / `1080p` |
| `image` | **object** | нет | внутри `file_id` ИЛИ `url`, взаимоисключающие |
| `reference_images` | array | нет | картинки-референсы |
| `reference_audios` | array | нет | максимум 3 клипа, по 15 секунд каждый |
| `output` | object | да (по справочнику) | внутри обязательный `upload_url` (подписанная ссылка) |
| `storage_options` | object | нет | `filename` (обязателен, если блок есть), `expires_after`, `public_url` |
| `user` | string | - | идентификатор конечного пользователя |

Дословно из справочника: поле называется `image`, и он «also accepts `image_url` for compatibility».

Ответ на POST: `{"request_id": "..."}` и больше ничего.

Ответ GET `/v1/videos/{request_id}`:
- `status` - `pending` / `done` / `failed`;
- `progress` - целое 0-100, отсутствует при `failed` (наш поллер это поле не читает - можно показывать прогресс, но мы не показываем);
- `video.url` - ссылка на готовый файл;
- `video.duration` - секунды;
- `video.respect_moderation` - булево, отметка модерации;
- `usage.cost_in_usd_ticks` - цена в тиках (наш код делит на 1e10);
- `usage.total_tokens` - вход + выход в токенах (то есть токены у видео всё-таки считаются, хотя тарификация посекундная);
- `error` - только при провале, внутри `code` и `message`.

ПРОТИВОРЕЧИЕ, которое надо знать: справочник помечает `output` как обязательный (внутри подписанная ссылка для заливки результата), а наш `gen_media.py` его не шлёт вообще и при этом получает готовые файлы через `video.url` / `file_output.public_url` уже месяцами. Значит либо справочник описывает более новую ревизию API, либо `output` обязателен лишь для сценария «залей мне в моё хранилище». Практический вывод: не добавлять `output` в наш код без нужды, работающая схема - без него.

## 2. Лимиты и очередь

Источник: https://docs.x.ai/developers/rate-limits (сверено 2026-09-10).

ЗАМЕРЕНО (дока), лимит измеряется в запросах В СЕКУНДУ, не в минуту:

| тир | `grok-imagine-image` | `grok-imagine-video` |
|---|---|---|
| 0 | 6 RPS | 10 RPS |
| 1 | 12 RPS | 20 RPS |
| 2 | 25 RPS | 39 RPS |
| 3 | 50 RPS | 79 RPS |
| 4 | 100 RPS | 158 RPS |

TPM для imagine-моделей в доке проставлен прочерком - потолка по токенам нет.
Превышение любого лимита - `429 Too Many Requests`. Структура ответа 429 и заголовки `x-ratelimit-*` в доке не описаны.
Cap конкурентности (сколько заданий может одновременно висеть в очереди) в доке НЕ указан вообще - ни одной цифры.

ВЫВОД ДЛЯ НАС, важный: даже нулевой тир даёт 10 запросов в секунду на видео. Наш `MAX_PARALLEL = 1` в `gen_media.py` - это НЕ серверный кап, а обход клиентской проблемы: в `tools/xai_http` нет обработки 429 и воркеры дерутся за refresh одного OAuth-токена (комментарий в коде, строки 36-38). Ограничение снимается починкой транспорта, а не переговорами с xAI. `bank_raw.py` уже гоняет `--jobs 3` и живёт.
Отдельно: наш доступ идёт по OAuth подписки SuperGrok, а не по платному ключу тира. К какому тиру приравнена подписка - НЕ ПРОВЕРЕНО, в доке этого нет.

ЗАМЕРЕНО (наш замер 2026-07-07, скил media-forge, C:\Users\Administrator\.claude\skills\media-forge\SKILL.md, строка 25): на нашем OAuth-доступе «конкурентность видео = 1 (параллель = 429)», в ответе замечен заголовок `x-ratelimit-limit-requests: 80`. Это прямо противоречит документированным 10 RPS нулевого тира. Правдоподобное объяснение: лимит на видео у подписки не по RPS, а по числу ОДНОВРЕМЕННО СЧИТАЮЩИХСЯ заданий, и такого поля в доке просто нет. Кто будет чинить транспорт - мерить надо самому, доке тут верить нельзя.

## 3. Image-to-video: что заявлено и почему у нас не сработало

### 3.1. Что заявлено

ЗАМЕРЕНО (https://docs.x.ai/developers/model-capabilities/video/image-to-video):
- Картинку можно отдать тремя способами: публичный URL, base64 data URI (`data:image/jpeg;base64,...`), либо `file_id` из Files API.
- Промпт при i2v НЕОБЯЗАТЕЛЕН: «Sending `image` alone is image-to-video».
- `grok-imagine-video-1.5` поддерживает нативные 1080p на image-to-video.
- Максимальный размер файла, допустимые длительности и коды ошибок на странице не указаны.

ЗАМЕРЕНО (REST-справочник): поле называется `image` и это ОБЪЕКТ с `file_id` или `url` внутри (взаимоисключающие). Плоское `image_url` справочник упоминает как принимаемое «for compatibility».

ЗАМЕРЕНО (https://x.ai/news/grok-imagine-video-1-5): 1.5 подаётся именно как i2v-модель - «better motion, better physics, better audio». Video 1.5 Fast делает 6 секунд 720p примерно за 25 секунд против 40+ у предыдущей модели.

### 3.2. Наши замеры: два разных провала, не один

**Замер 2026-07-07 (media-forge, строка 30) - самый подробный.** Дословно: «img2video (оживить готовую картинку) НЕ разгадан. video-1.5 требует живой http image_url, но отвергает всё перебранное: imgen-url -> 400 "text-to-video not supported", b64/data-uri -> 400, свежий imgen-url -> 400».
Разбор ошибки: текст `text-to-video not supported` при ОТПРАВЛЕННОЙ картинке означает, что сервер картинку в запросе НЕ УВИДЕЛ и посчитал запрос текстовым, а 1.5 на тот момент text-to-video не принимала. То есть картинка терялась на разборе тела запроса.

**Замер 2026-05-09 (env_bank.py, строки 6-7; build_short.py, строка 946): «image-to-video не работает».** Записан без текста ошибки, поэтому как отдельное доказательство слаб - скорее повторение того же грабля.

### 3.3. Рабочая версия причины (наша гипотеза, требует одного дешёвого замера)

Наш код шлёт ПЛОСКУЮ строку:
- `C:\Users\Administrator\Documents\git\shortsmaker\vps\gen_media.py`, строки 158-159: `payload["image_url"] = image_url`;
- `C:\Users\Administrator\Documents\git\shortsmaker\vps\director.py`, строки 139-141: `"image_url": "data:image/jpeg;base64," + b64`.

Справочник же требует вложенный объект: `"image": {"url": "https://..."}` либо `"image": {"file_id": "..."}`.

Значит проверять надо по порядку, каждый шаг отдельным запросом:
1. `{"image": {"url": "<публичный http-адрес>"}}` - канонная форма, вероятность успеха самая высокая;
2. `{"image": {"url": "data:image/jpeg;base64,..."}}` - data URI внутри объекта (страница i2v data URI разрешает явно);
3. `{"image": {"file_id": "..."}}` через Files API - если временные ссылки не годятся;
4. только если всё выше упало - возвращаться к плоскому `image_url`.

Дополнительный подозреваемый по замеру 07-07: временные ссылки `imgen.x.ai` не качаются программно (403 и с авторизацией, и без; media-forge, строка 23). Если xAI дёргает наш `url` своим загрузчиком, он упрётся в тот же 403. Отсюда: картинку класть на СВОЙ публичный адрес, а не подсовывать ссылку из ответа imagen.

НЕ ПРОВЕРЕНО и важно: замер 07-07 утверждает, что «grok-imagine-video-1.5 = ТОЛЬКО image->video, text2video отвергает» (media-forge, строка 26). Дока 2026-09 прямо говорит обратное: 1.5 умеет t2v и именно на t2v даёт 1080p. Замеру два месяца, за это время вышла публичная 1.5. Перед любым переводом банка среды на 1.5 сделать один пробный t2v-запрос и посмотреть, не 400 ли это. Планировать переезд, не проверив, - нельзя.

## 4. Цена: сверка доки с нашим счётом

ЗАМЕРЕНО (дока): `grok-imagine-video` 0.050 usd/с, `grok-imagine-video-1.5` 0.080 usd/с, разрешение цену НЕ меняет.

ЗАМЕРЕНО (наш прогон 09.09, docs\research\broll\imagine.md, строка 38): 167 видео обошлись в 77.21 usd, то есть 0.46 usd за клип в среднем.

Сверка арифметикой: 77.21 / 0.05 = 1544 секунды видео на 167 клипов. При наших двух рабочих длительностях (`env_bank.py --dur 8` и `bank_raw.py --dur 10`) это ровно смесь примерно 63 клипов по 8 с и 104 по 10 с. Сходится. Вывод: посекундная цена доки совпадает с тем, что реально списывает счётчик `cost_in_usd_ticks` на нашем OAuth-доступе, и никакой надбавки за 720p нет.

НЕСХОДИМОСТЬ, которую надо держать в голове: в памяти этой машины записана цифра «видео 6 секунд = 0.42 usd». По цене доки 6 секунд классики стоят 0.30, а 1.5 - 0.48. Цифра 0.42 не ложится ни туда, ни туда. Скорее всего это старая цена до публичного релиза 1.5. При планировании бюджета опираться на посекундный тариф и на свой `usage.jsonl`, а не на эту цифру.

Что это даёт по деньгам (посчитано по тарифу доки, у нас НЕ проверено):
- клип 8 с классикой = 0.40 usd, на 1.5 = 0.64 usd;
- клип 10 с классикой = 0.50 usd, на 1.5 = 0.80 usd;
- переход на 1.5 дороже ровно в 1.6 раза при любой длительности, и разрешение 1080p при этом БЕСПЛАТНО (цена от разрешения не зависит).

ВНИМАНИЕ, дока сама себе противоречит по разрешению. Страница моделей (https://docs.x.ai/docs/models) даёт одну цену за секунду на модель, без разбивки. Страница-гайд (https://docs.x.ai/docs/guides/video-generations) пишет дословно: «Video generation uses per-second pricing where both duration and resolution affect the total cost». Одна из двух страниц врёт, и НЕПОНЯТНО какая.
Как разрешать: не спорить, а замерить. Один клип 8 с в 480p, один в 720p, один в 1080p, посмотреть `usage.cost_in_usd_ticks` в ответе GET. Три клипа стоят меньше двух долларов и закрывают вопрос навсегда. До этого замера бюджет считать по худшему варианту (цена растёт с разрешением).

Отсюда практический вывод, который стоит вынести в сам скил: **мы гоняем 720p, хотя вертикаль у нас 1080x1920, и 1080p может не стоить ничего сверху.** Наш кап 720p - это `choices=["480p","720p"]` в `gen_media.py`, строка 254, и умолчание функции; API 1080p отдаёт (у `grok-imagine-video-1.5`, t2v и i2v). Первым делом мерить цену 1080p, потом снимать кап.
Осторожно: сторонние агрегаторы берут иначе, у них цена от разрешения ЗАВИСИТ (по данным нашего прошлого прогона: OpenRouter/kie 480p 0.08, 720p 0.14, 1080p 0.25 usd/с; EvoLink 480p 0.064, 720p 0.112). Это ПРАКТИКА для сравнения, к нашему прямому доступу в api.x.ai отношения не имеет. Заметь: у агрегаторов разрешение цену двигает - это косвенный довод в пользу того, что права страница-гайд, а не таблица моделей.

## 5. Как ведёт себя очередь (операционное)

Всё ЗАМЕРЕНО (дока), источник https://docs.x.ai/developers/model-capabilities/video/generation:
- «Video generation is an asynchronous process that typically takes up to several minutes to complete». Время зависит от сложности промпта, длины, разрешения и режима правки.
- Официальный SDK поллит с интервалом 100 миллисекунд по умолчанию; в примерах на голом REST дока спит 5 секунд между проверками. Обязательного интервала нет.
- «Videos are returned as temporary URLs». Срок жизни ссылки НЕ указан. Управлять сроком можно через `storage_options.expires_after`.
- Сколько живёт `request_id` до статуса `expired` - НЕ указано.
- Ошибка `invalid_argument` в списке кодов включает случай «a prompt that is too long». То есть предел длины промпта существует, но числом нигде не назван. Практический потолок для нас: наши рабочие тела 20-60 слов далеко под любым разумным лимитом, специально упираться незачем.
- `respect_moderation` в ответе: клипы, зарезанные модерацией, блокируются; критерии не расписаны.

ГРАБЛЯ НАШЕГО КОДА, найдена этой сверкой: `POLL_TIMEOUT = 240` в `gen_media.py`, строка 31, то есть 4 минуты. Дока обещает «up to several minutes». На 720p/8 с мы в лимит укладываемся, но при переходе на 1080p или на 12-15 секунд клип может честно считаться дольше четырёх минут, и наш код объявит его упавшим, хотя xAI его досчитает и спишет деньги. Поднимать `POLL_TIMEOUT` ДО перехода на 1080p, иначе получим оплаченные, но выброшенные клипы. Заодно `progress` (0-100) из ответа GET можно печатать в лог - сейчас мы это поле игнорируем.

## 6. Чего в API нет вообще (и что из этого следует для промптинга)

ЗАМЕРЕНО (дока, полный обход страницы генерации и REST-справочника):
- нет `seed`;
- нет `negative_prompt`;
- нет `guidance_scale` / `cfg`;
- нет `n` для видео (у картинок `n` есть, до 10 - media-forge, строка 23);
- нет `style` / `style_preset`;
- нет управления частотой кадров и битрейтом.

Следствия, на которых стоит весь скил промптинга:
1. **Воспроизводимости нет.** Один и тот же промпт даёт разный клип. Отбор - только перебором: снять несколько копий сюжета и выбрать. Наши скрипты так и устроены (`--per 3` в `env_bank.py`, `--per 4` в `bank_raw.py`).
2. **Всё управление - в тексте промпта.** Запреты («без людей, без надписей») пишутся словами внутри промпта, потому что поля `negative_prompt` не существует. Наш `ENV_TAIL` в `env_bank.py`, строки 40-42, - это ручная замена отсутствующему параметру.
3. **Звук генерируется всегда, пока не выключишь.** `generate_audio` по умолчанию `true`, мы его не передаём, значит платим временем генерации за звуковую дорожку, которую монтаж выбрасывает. Отключение: `generate_audio: false`. Ускорит ли это генерацию - НЕ ПРОВЕРЕНО, но дорожка точно лишняя. Побочный довод: пока звук включён, модель кладёт в движение музыкальный ритм, и сообщество лечит это словами `no music` прямо в промпте.
