# shortsmaker

Конвейер: тема из базы TechPulse → сценарий Гроком → озвучка Grok TTS → визуал Grok Imagine → монтаж ffmpeg → черновик в телеграм.

Всё исполняется **на VPS <VPS_IP>**, потому что там живут hermes (OAuth-подписка Grok), ffmpeg и база новостей. Локальная машина только запускает.

```bash
py "$SCRATCH/run_remote.py" "$SCRATCH/команды.py"   # paramiko, вход только по ключу ~/.ssh/gspc_deploy
```

Скрипты этого скила — источник правды. Рабочие копии лежат на VPS в `/opt/shorts/`.

## Проверено на бою 2026-08-13/14

| что | как | цена | результат |
|---|---|---|---|
| картинка | `POST api.x.ai/v1/images/generations` | $0.02–0.08 | `resolution:"2k"` = 1584×2816, `aspect_ratio:"9:16"` работает параметром |
| видео | `POST api.x.ai/v1/videos/generations` + опрос | **$0.07/сек** | 4/6/10/15 сек проверены, цена линейная; 720p потолок (1080p — явный отказ модели); всегда со звуком; генерация ≈ 11–15× реального времени |
| image-to-video | то же + `image_url`, модель `grok-imagine-video-1.5` | **$0.14/сек** | оживляет наш кадр, вдвое дороже t2v |
| extend | `POST /videos/extensions`, поле **`video: {"url": ...}`** — не `video_url`! | $0.46 за +6 сек | файл приходит целиком (исходник+продление) — цепочка сцен единым пространством работает |
| edit | `POST /videos/edits` | — | эндпоинт живой, глубоко не зондирован |
| скрин новости | `news_shot.py` через `/opt/hermes/venv` | бесплатно | 1080×1922 мобильной колонкой, полная страница — под кроп-панораму |
| озвучка | `tools.tts_tool._generate_xai_tts` | бесплатно (подписка) | mp3 24 кГц, ru; **28 голосов**, не два |

**Голоса.** `GET https://api.x.ai/v1/tts/voices` отдаёт 28 мультиязычных: altair, ara, atlas,
aurora, carina, castor, celeste, cosmo, eve, helios, helix, iris, kepler, leo, liora, lumen,
luna, lux, naksh, orion, perseus, rex, rigel, sal, sirius, ursa, zagan, zenith. Дефолт `eve`
женский — для технического канала перебрать мужские. Меняется через `SHORTSMAKER_VOICE`.

**ГРАБЛЯ: клонирование голоса на xAI недоступно из РФ. Два независимых гейта.**

Путей создания голоса два, и правила у них разные:

| путь | цена | гейт |
|---|---|---|
| консоль console.x.ai | **бесплатно, до 30 голосов** | **США, кроме Иллинойса** (BIPA) |
| `POST /v1/custom-voices` | — | **только Enterprise-план** |

Замер 08-14 (OAuth-токен подписки, tier 5 = SuperGrok Heavy, VPS Франкфурт):
`GET /v1/custom-voices` → 200 `{"voices":[],"total_count":0,"cap":30}` (реестр есть, токен
авторизован, cap 30 = тот самый бесплатный лимит консоли);
`POST /v1/custom-voices` → **403 `{"error":"Custom voices are not enabled for this team."}`**
— это Enterprise-гейт, к гео отношения не имеет.

Консольный путь Enterprise НЕ требует и Heavy его включает — но раскатан только на США.
Регион считается **по трём признакам сразу: IP + страна X-аккаунта + платёжный профиль**
(OFAC/EAR). Поэтому **US-VPN бесполезен** — аккаунт и профиль остаются РФ. Публичных
успешных кейсов из СНГ нет (спрошено у Грока с x_search, 08-14).

В приложении Grok (grok.com, iOS, Android) клонирования **нет вообще** — только пресеты.

**ГРАБЛЯ: у аккаунта две разные team_id.** Токен подписки живёт в одной команде
(`/me` покажет свою), а console.x.ai при первом входе заводит ДРУГУЮ, пустую. Пополнение
баланса на странице консоли уйдёт команде, которой hermes не пользуется. Всегда сверять
`team_id` из `GET /v1/me` с тем, что в адресе консоли.

Клон голоса — только Chatterbox локально на GPU (MIT-веса, русский, ~3.5 ГБ VRAM),
через `tts.providers.<name>` с `type: command` — правок кода ноль. Вшивает неслышимый
вотермарк PerTh, это дизайн модели.

Токен берётся из `~/.hermes/auth.json` через `resolve_xai_http_credentials()` — **платный `XAI_API_KEY` не нужен**, работает OAuth подписки. Тот же резолвер обслуживает TTS и vision-судью.

**Нарративная петля (правило Гора 08-14).** Сценарий не пишется одним куском —
визуал сцены строится РАНЬШЕ её текста. Цикл: слайд → `perceive()` смотрит на него
глазами зрителя (grok-4.3 vision: что видит, что цепляет, эмоция, оставшийся
вопрос) → `story_step()` пишет реплику ИЗ этой реакции и заказывает следующий
кадр под вопрос зрителя. Четыре стадии: hook (карточка инфоповода) → explain
(генеративный кадр, придуманный под вопрос из hook) → reaction (карточка
реальных комментариев) → forecast (наш прогноз из всей цепочки). Реплика не
пересказывает слайд — отвечает на реакцию.

**Чередование кадров (правило Гора 08-14).** Нечётные сцены — панорама по скрину новости-первоисточника: там настоящий товар, это документальный слой. Чётные — генеративный футаж, который не притворяется товаром (вымышленный датацентр, метафора). Плашек нет — регистр сам говорит, что это не товар. Реализовано в `build_short.py`: скрин через `news_shot.py`, футаж — видео с фолбэком на кен-бёрнс от картинки.

**ГРАБЛЯ: на VPS уже есть браузерная инфраструктура.** `/opt/hermes/venv` (camoufox + playwright 1.60, авито-скрейпинг, `avito_photos.py`) и кэш `/root/.cache/ms-playwright/chromium-1228`. Свои venv и браузеры НЕ ставить; несовпадение сборки playwright и кэша решается `executable_path` с глобом `chromium-*/chrome-linux*/chrome`.

## Что делает скрипт, а что решает агент

Граница жёсткая. Агент **не переписывает** ffmpeg-команды и не трогает поллинг.

| детерминированное — в `scripts/`, не трогать | творческое — решает агент |
|---|---|
| вызовы api.x.ai, поллинг видео, ретраи, 429 | сценарий и раскадровка |
| TTS и склейка аудио | промпты сцен |
| ffmpeg: масштаб, kenburns, xfade, субтитры, энкод | выбор голоса eve/rex |
| ffprobe-гейт и отправка в телеграм | отбор годного дубля |

Единственный интерфейс между ними — JSON плана съёмки (`shots`).

## Конвейер

### 1. Тема

```bash
docker exec news_postgres psql -U news_user -d news_aggregator -tAc "<запрос>"
```

Берём сюжет с сильной реакцией, которого не было в роликах 30 дней. Дедуп **и по `news_id`, и по `story_id`** — иначе один сюжет уедет четырьмя новостями.

Полезные колонки: `translated_title`, `translated_description`, `relevance_score`, `story_id`.
В `vox_reactions.verdict_json` лежит готовый материал: `one_liner`, `top_objections`, `memes`, `valence`, `intensity`.

**ГРАБЛЯ: колонок `title_ru`/`verdict` не существует** — это `translated_title` и `verdict_json`. Роль `postgres` тоже не существует, только `news_user`.

### 2. Сценарий

Grok через метер-прокси, чтобы расход попал в отчёт:

```
POST http://127.0.0.1:8650/v1/chat/completions
X-Meter-Source: shortsmaker
{"model": "grok-4.3", "messages": [...], "max_tokens": 1600}
```

**ГРАБЛЯ: заголовок именно `X-Meter-Source`**, не `X-Source` — иначе расход запишется как `app` и потеряется в общей куче.
**ГРАБЛЯ: `effort` не передавать никогда** — прокси на нём падает.

Нормы хронометража: **32–45 секунд, целиться в 38**. Русский TTS идёт 2,2–2,5 слова в секунду, значит **90–110 слов** текста. Одна сцена = одна мысль = 12–18 слов. Потолок 59 секунд — за минутой ролик выпадает из шортс-лент.

Цифры в тексте для озвучки писать **словами**: синтез читает «$4700» как попало.

### 3. Озвучка — по фрагменту на сцену

```python
from tools.tts_tool import _generate_xai_tts
_generate_xai_tts(text, "/opt/shorts/work/v0.mp3", {"xai": {"language": "ru", "voice_id": "eve"}})
```

Пофрагментно, а не одним куском: тогда длительность каждой сцены известна точно и картинка меняется ровно по фразе, а не по таймеру.

**ГРАБЛЯ: по умолчанию `language="en"`** — русский текст без явного `ru` читается с акцентом.

### 4. Визуал

Сначала пробуем уровень 1, при отказе падаем ниже. Решает **скрипт по exit-коду**, не модель.

| уровень | чем | когда |
|---|---|---|
| 1 | `grok-imagine-image-quality` + ffmpeg zoompan | базовый, $0.05 за сцену |
| 2 | `grok-imagine-video` | только hero-кадр, $0.42 за 6 сек |
| 3 | типографские карточки (`make_short.py` старый) | генерация недоступна |

Картинка:

```bash
curl -sS https://api.x.ai/v1/images/generations \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"model":"grok-imagine-image-quality","prompt":"...","n":1}'
# -> {"data":[{"url":"https://imgen.x.ai/...","mime_type":"image/jpeg"}],"usage":{"cost_in_usd_ticks":500000000}}
```

Видео:

```bash
curl -sS https://api.x.ai/v1/videos/generations \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -H "x-idempotency-key: $(uuidgen)" \
  -d '{"model":"grok-imagine-video","prompt":"...","duration":6,"aspect_ratio":"9:16","resolution":"720p"}'
# -> {"request_id":"..."}
curl -sS https://api.x.ai/v1/videos/$REQUEST_ID -H "Authorization: Bearer $TOKEN"
# опрашивать раз в 5 с до status=="done"; терминальные: failed / error / expired / cancelled; таймаут 240 с
```

**ГРАБЛЯ: ссылки временные.** `imgen.x.ai/xai-tmp-...` живёт недолго — качать сразу в том же запуске, не откладывать.

**ГРАБЛЯ: `image_generate_tool` из hermes в Грок НЕ ходит** — он ходит в FAL.ai и без `FAL_KEY` мёртв. Только прямой вызов api.x.ai.

**ГРАБЛЯ: наш прокси `:8645` imagine не несёт.** Там ровно шесть путей: `/v1/responses`, `/v1/chat/completions`, `/v1/completions`, `/v1/embeddings`, `/v1/models`, `/health`. Генерация только напрямую в `api.x.ai`.

**ГРАБЛЯ: в `/root/.hermes/config.yaml` нет секции `video_gen`** — штатный резолв провайдера вернёт `None` и хендлер упадёт в `no_provider_configured`. Провайдера подсовывать вручную.

**ГРАБЛЯ: разрешение только 480p/720p.** 1080p у Grok Imagine нет, финальные 1080×1920 получаются апскейлом.

**ГРАБЛЯ: параллелить генерацию нельзя.** В `xai_http.py` нет ни семафора, ни backoff, ни обработки 429, а все воркеры делят один OAuth-токен и устраивают гонку refresh. Пул максимум 2–3, перед фан-аутом один раз прогреть токен `resolve_xai_http_credentials(force_refresh=True)`. Залп из 15 параллельных вызовов выжигает `credential_pool` и роняет всё в 401 — лечится `hermes auth reset xai-oauth`.

Про промпты — `references/prompts.md`.

**Честность визуала (фидбек Гора 08-14).** Сгенерированный кадр не имеет права
выдавать себя за фото обсуждаемого товара — зритель не знает, как выглядит
настоящий продукт, и фотореалистичная выдумка вводит его в заблуждение. Правила:

1. Генеративный кадр — всегда **обобщённая иллюстрация категории** («радиатор
   вообще»), конкретную модель и узнаваемый дизайн товара не изображать —
   зашито в промпт сценариста.
2. В каждом ролике с генеративным визуалом стоит плашка
   «изображение сгенерировано · иллюстрация» (рисует `assemble`, не убирать).
3. Настоящий товар показывать **только реальным фото**: положить файл в
   `/opt/shorts/real_photos/` и передать путь в `card["photo"]` — скрипт возьмёт
   его вместо генерации. Реальное фото всегда важнее сгенерированного.

### 5. Монтаж

Рецепты — `references/ffmpeg.md`. Коротко:

```bash
# картинка -> клип с наездом, длительность по фразе TTS
ffmpeg -nostdin -y -loop 1 -t $T -i scene.jpg -filter_complex \
 "scale=4320:7680:force_original_aspect_ratio=increase,crop=4320:7680,\
zoompan=z='min(zoom+0.0012,1.20)':x='iw/2-(iw/zoom/2)':y='ih/2-(ih/zoom/2)':d=$((30*T)):fps=30:s=1080x1920,setsar=1" \
 -c:v libx264 -pix_fmt yuv420p -r 30 clip.mp4
```

**ГРАБЛЯ: zoompan без предварительного апскейла дрожит.** Апскейл ×4 обязателен.

**ГРАБЛЯ: ffmpeg читает stdin и съедает остаток bash-скрипта.** Всегда `-nostdin`, а в питоне `stdin=subprocess.DEVNULL`. У `ffprobe` флага `-nostdin` нет — там только DEVNULL.

**ГРАБЛЯ: `xfade` падает**, если у входов разные fps, размер или pix_fmt. Приводить всё к `1080x1920, fps=30, yuv420p` до склейки.

Субтитры дублировать обязательно: лента стартует без звука, а термины железа синтез съедает. `MarginV≈380` держит текст выше зоны интерфейса.

### 6. Гейт — обязателен

```bash
bash scripts/verify.sh out.mp4
```

Отчитываться об успехе **только при exit 0** и вставлять вывод ffprobe в ответ. Проверяет: 1080×1920, есть оба потока, длительность в допуске, расхождение видео и аудио меньше 0,3 с, полный декод без ошибок.

### 7. Доставка

Черновик во внутреннюю группу GSPC, `sendVideo` с `supports_streaming=true`, `width`, `height`, `duration`.

**ГРАБЛЯ: без `-movflags +faststart` и `yuv420p` телеграм отдаст ролик документом**, а не видео.

Публиковать наружу — только с явного согласия человека.

## Снос рекламных оверлеев в news_shot.py (08-21)

Перед скриншотом `news_shot.py` удаляет из DOM всё, что перекрывает статью:
fixed/sticky-элементы крупнее 40% экрана, блоки с классами reklama/advert/adfox/
banner/promo/popup/modal/overlay/cookie/consent, крупные iframe. Плюс блок-маркеры
пополнены («решение деликатной проблемы», «реклама 18+»). Без этого mail.ru и
подобные лепят рекламу поверх контента, и она уезжает в кадр.

## Готовый сценарий извне: `--script-json` (08-21)

Когда драматургия и гейт честности приходят хендоффом (а не изобретаются петлёй),
слова пишет режиссёр, конвейер только исполняет:

```bash
build_short.py --theme-json тема.json --script-json сценарий.json --dubles 4 --no-send
```

Формат сценария:
```json
{"theme":"...", "tg_caption":"...",
 "kinds":["news_shot","footage","footage","comment","footage"],
 "cards":[{"voice":"...","big":"...","caption":"...","shot":"..."}]}
```
- `kinds` задаёт тип каждой сцены явно; длина = числу карточек (можно 5+, не только 4)
- `shot` — промпт кадра ИМЕННО этой сцены; пустой = кадра не будет (для news_shot/comment)
- при `--script-json` нарративная петля (`perceive`/`story_step`) НЕ запускается

## ТРЕТИЙ ГЕЙТ: платформенная связность (08-22)

`platform_gate.py` ловит то, что покадровый гейт не увидит **по устройству**:
ошибку не в кадре, а в СОЧЕТАНИИ. Процессор AMD законен. Гнездо Intel законно.
Процессор AMD в гнезде Intel невозможен — но на вопрос «годен ли кадр» такое
отвечает «годен», потому что каждая половина по отдельности в порядке.

```bash
/opt/hermes/venv/bin/python3 /opt/shorts/platform_gate.py <video.mp4>   --theme theme_<slug>.json --script script_<slug>.json --step 3.0 [--strict]
```

Встроен в `build_short.py` третьим по счёту, после `verify.sh` и `frame_gate.py`.

### Что проверяет

- **внутри кадра:** процессор одной марки на плате другой; ножки на процессоре
  у Intel (настольные Intel всегда LGA); длинная настольная планка внутри
  ноутбука; разъём с числом жил, которого не бывает;
- **против платформы ролика:** марка процессора и видеокарты, стиль сокета
  (AM5 — это LGA, AM4 — PGA), тип памяти;
- **между кадрами:** две разные марки процессора, платы или видеокарты в одном
  ролике;
- **сценарий против платформы:** голос про Intel в ролике про AMD, «GeForce» в
  ролике про Radeon, и счётный контроль 12V-2x6 (12 силовых жил в два ряда плюс
  4 сигнальных — «шесть контактов» блокируется).

### Устройство, оплаченное замерами

1. **Судья описывает, логика судит.** Спрашивать «это AMD в интеловском
   гнезде?» нельзя: модель соглашается с подсказкой. Спрашиваем нейтрально, а
   вывод делает код по таблице несовместимостей.
2. **Один вопрос — один признак.** ЗАМЕРЕНО: многополевое извлечение эта модель
   не держит — то отвечает по существу, то штампует «не видно» по всем полям и
   подмешивает отсебятину («Ответ дан с AI»). Узкие вопросы устойчивы.
3. **Счёт жил ненадёжен в абсолюте.** ЗАМЕРЕНО: на соседних кадрах 16 и 12 при
   одинаковых разъёмах, на третьем 8/6/8. Поэтому блокируется не «не то число»,
   а число, которого не бывает вовсе, и только при единогласии трёх голосов.
4. **Вопрос про форму без оговорки врёт.** На крупных планах деталей уверенно
   отвечал «ноутбук» — шесть ложных подозрений на ролике, где ноутбука нет.
   Отказ от ответа надо разрешать явно.
5. **Слепота обязана быть видимой.** Кадры без железа считаются отдельно; если
   железа не нашлось нигде, гейт говорит вслух, что его молчание ничего не
   подтверждает.

- подсунут ложный сокет AM4 при LGA-гнёздах в кадре: **4 ошибки, заблокирован**;
- пять текстовых случаев: GeForce при AMD, Ryzen при Intel, Core Ultra при AMD,
  «12VHPWR на шесть контактов» — все пойманы; согласованный текст пропущен.
