# Петля «OCR → критик → судья → новый проход»

Гор 22.09.2026: «оцр производит критику, критик пишет критику, судья берёт изначальный промпт, критику
ошибок и, используя скил, пишет промпт на исправление ошибок и новый проход». Реализация —
`shortsmaker/vps/frame_critic.py` (копия на хабе `/opt/shorts/frame_critic.py`). Всё локально: модели
на домашней 5090 через Ollama, ни квоты подписки, ни денег.

## Запуск

```bash
# на хабе <VPS_IP>, каталог ролика с script.json, work/karaoke_words.json, fact_gate.json
python3 /opt/shorts/frame_critic.py /opt/shorts/fe9 --video out/fe9-home.mp4 --vision-every 15
# повторный прогон без моделей (только код + отчёт по готовым jsonl): --skip-models
```

Каждая ступень пишет свой файл по ходу в `<dir>/critic/`; упавший прогон продолжается с места,
уже разобранные кадры не пересчитываются.

## Ступени

| # | Что | Модель | Файл | Цена |
|---|---|---|---|---|
| 1 | OCR **каждого** кадра (540 px по ширине) | qwen3-vl:8b-instruct, `think:false`, num_predict 160 | `ocr.jsonl` → `titles.json` (отрезки одинакового текста) | 0,7 с/кадр = 10 мин на 30 с ролика |
| 2 | Зрение каждого N-го кадра: сцена, руки, артефакты, обрезан ли текст | qwen3-vl, JSON по схеме | `vision.jsonl` | ~1,5 с/кадр |
| 3 | Кодовые проверки без модели | — | `code_checks.json` | 0 |
| 4 | Критик: все претензии с таймкодом и цитатой | **sudya** (122B) | `critique.json` | ~2 мин |
| 5 | Судья: исправленные реплики, титры было/стало, указания сборщику, какие сцены перегенерировать | sudya + правила скила | `fix_prompt.json` | ~2 мин |
| 6 | Отчёт человеку | — | `REPORT.md` | 0 |

Кодовые проверки (ступень 3): титр короче 1,5 с; слово разорвано переносом (обрывок строки в 1–2 буквы —
такое было в дайджесте 22.09: «ПРОГИБАЕТС / Я»); титр без единого слова из сценария; голос идёт, а титра
нет дольше 4 с.

## Почему так, а не иначе

- **glm-ocr через Ollama зацикливается** («ПОЛУЧИЙТЕ ТЕКСТ» × 300, 298 с на кадр). С `num_predict` 120 отвечает, но
  оборачивает в markdown и всё равно повторяется. qwen3-vl 8B читает титры чисто за 0,4–0,9 с — он и OCR, и зрение.
- OCR каждого кадра, а не выборка: «покадровый» значит покадровый, а слитые отрезки одинакового текста и дают
  точное время жизни титра. Зрение — выборкой, потому что сцена меняется раз в секунды.
- Критик и судья — **разные вызовы** одной модели с разными ролями: критик ищет всё, судья решает, что чинить.
  Слить в один вызов — получить размытый ответ (см. `sudya-1000-glaz`, принцип узких линз).
- Судья получает **исходный сценарий целиком** и правила канала: он переписывает реплики, а не комментирует.
  Его `script_lines` и `title_fixes` — вход для нового прохода сборщика.

## Новый проход — `vps/critic_loop.py` (дайджест)

```bash
/usr/local/lib/hermes-agent/venv/bin/python3 /opt/shorts/critic_loop.py /opt/shorts/critic_digest_1244     --video /opt/shorts/out/gen-20260922-1244.mp4 --max-rounds 3 [--send]
```
Круг: `frame_critic --kind digest --rules lab/digest_rules.txt` → судья отдаёт `scenes` в формате сборщика
(voice с одним `<slow>`, title, hl, eyebrow, footage_hint) → `digest_short.lint` → `digest_short.build --no-send`
→ новый ролик → следующий круг в `round<N>/`. Останов: критик `ok`, список претензий не изменился, лимит кругов,
линт не прошёл — дальше человек. Журнал `loop.log` пишется по ходу. Интерпретатор — только venv Гермеса
(системный python3 без httpx роняет озвучку).

`fix_prompt.json` содержит: `script_lines` (реплики в исходном порядке), `title_fixes` (t, было, стало, почему),
`builder_instructions`, `regenerate_scenes` (индексы), `keep_as_is`. Сборщик (`build_short.py` / сценарий ролика)
получает новый `script.json` из `script_lines`; перегенерируются только сцены из `regenerate_scenes`. После сборки —
снова `frame_critic.py`. Останов: критик выносит `ok` или два круга подряд не меняют список претензий.

## Что судья НЕ решает

Факты. Если критик нашёл цифру не из базы (`fact_gate.json`), это возвращается человеку, а не переписывается моделью:
судья вправе убрать цифру, но не подобрать новую.

## Грабли первого дня (22.09.2026, FE9)

- **Переполнение контекста режет начало.** 134 дрожащих OCR-замечания + 30 КБ зрения выдавили сценарий из 32k, критик ответил «сценарий не предоставлен», судья — «менять нечего». Теперь: слияние похожих прочтений титра (≥ 0,8), вспышки в 1–2 кадра выбрасываются, бюджет промпта, сценарий и факты первыми.
- **OCR в один слой смешивает титры и этикетки.** На коробках RTX 5080 двадцать строк маркировки вытеснили настоящий титр «RTX 5080 FE · запакованные» за лимит токенов → критик решил, что титра нет. Теперь OCR отдаёт `overlay` и `printed` раздельно; этикетки идут критику отдельным списком с вопросом «уместно ли показывать» (там были Carton ID, объём поставки и код клиента).
- **Зрение 8B выдумывает предметы и артефакты.** Алюминиевый кейс назвало «гитарой», красно-зелёный студийный поролон — «цветовыми искажениями»; судья послушно приказал «убрать гитару» и «перегенерировать сцены». В промпте зрения теперь названа декорация, артефакты — только генерации и сжатия, неопознанное — «предмет».
- **Судья достраивает факты.** OCR прочитал штамп 2025-12-18, судья написал «QC 2023, риск для новинки». Запрет в system: даты и номера только буква в букву из критики, сомнение — «проверить глазами».
- **Судья и зрение не помещаются на карту вместе.** При загруженном sudya (29 ГБ на карте) qwen3-vl уехал на процессор: 33 с на кадр вместо 0,7. Перед OCR выгружаем судью, перед критиком — зрение (`unload()`, keep_alive 0).
- **Бегущая строка речи — не титр.** Караоке-подпись меняется каждые полсекунды; в один слой с заголовками она дала «системное мелькание титров». OCR теперь в три слоя: `title` (заголовок сцены), `caption` (строка речи, проверяется по словам сценария), `printed` (на предметах).
- **Латиница = кириллица для OCR.** «HA» и «НА» неразличимы; критик объявил опечаткой. Нормализация омоглифов в коде и запрет в промпте.
- **Кадр не про то.** Зрение верно увидело автомобильную панель под речь о чипе MediaTek, но критик не связал кадр с репликой. Теперь каждой заметке зрения приписывается реплика, звучащая в этот момент.
- Выход судьи — **черновик правок для человека**, не команда сборщику: автоматический новый проход включать только после двух кругов без выдуманных претензий.
